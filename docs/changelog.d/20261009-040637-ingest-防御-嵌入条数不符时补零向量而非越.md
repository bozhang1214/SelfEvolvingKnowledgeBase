## 2026-10-09（`ingest` 防御：嵌入条数不符时补零向量，而不是越界崩溃）

- **背景**：上一轮把嵌入端口的失败契约定为"**同数量零向量**"（见 `EmbeddingProvider.embed` 的 KDoc）。
  但那条契约是**跨语言**的（Kotlin ↔ Swift/ArkTS），各端实现未必守得住；而 `KnowledgeIndex.ingest`
  当时是 `vector = vectors[i]` 的**裸索引**——一旦某端少返回一条，代价是**崩溃**
  （iOS 实测 `EXC_BREAKPOINT`，栈顶 `Kotlin_NSArrayAsKList_get`），不是一条可读的错误。
  "契约写在注释里"挡不住崩溃，所以补一层防御并把降级**报出来**。

- **改动**：
  - `apps/shared/.../rag/KnowledgeIndex.kt`：`provider.embed(...)` 结果少于切片数时，
    **补齐同维度零向量**再入库（零向量与任何向量余弦为 0 ⇒ 检索不命中，安全失败），
    并在 `IngestReport` 新增 `zeroFilled`（默认 0，向后兼容）**记录补齐条数**——
    静默补齐会掩盖真实缺陷，所以必须可被自检断言。
  - `apps/android/app/src/test/.../rag/KnowledgeIndexTest.kt`：新增
    `provider returning fewer vectors is padded instead of crashing`：用一个"故意只回 1 条"的
    假 provider，断言 `chunks ≥ 2`、`zeroFilled == chunks - 1`、全部切片都入库、零向量切片垫底得 0 分。
    ⚠️ 第一版这条测试**是空跑**（默认 `maxChars` 较大，30 次重复只切出 1 片 → `chunks >= 2` 直接失败）。
    已改成显式 `maxChars = 40, overlapChars = 0`，让"多片"确定发生——**测试自己也会骗人**。
