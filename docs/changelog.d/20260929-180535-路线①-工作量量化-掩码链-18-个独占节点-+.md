## 2026-09-25（M7 路线① 工作量量化；澄清 `Flatten` 的归属）

- **对 `ms-static-1x512.onnx` 做纯图结构分析（离线可做），得出两条关键结论**：

  1. **`Flatten` 只属于动态那份产物**：静态 ONNX 里 `Flatten` **算子数 = 0**
     （只有一个**名字**叫 `/m/Flatten`、`op_type` 却是 `Reshape` 的节点——早先重写保留原名所致）。
     所以动态 `.ms` 的 `FindBackendKernel nullptr: /m/Flatten` 来自**源模型自带的 Flatten**；
     而静态产物的 **0 CPU 挂起与 Flatten 无关，另有原因（尚未定位）**。
  2. **静态 ONNX 仍带完整动态链**（Shape×9 / ConstantOfShape×2 / Range×3 / Gather×15 / Where×5 / Expand×1）：
     输入虽已固定 1×512，这段"掩码展开"仍在图里。以 5 个 `Where` 输出做**反向切片**量化：
     - 掩码链总规模 **67 节点**；其中**不被 `input_ids` 主路径共享**（可安全删除上界）**18 节点**
       （Unsqueeze×5、Gather×5、ConstantOfShape×2、Cast×2、Slice/Range/Reshape/Mul 各 1）；
     - 边界消费者 **9 个**（含 `/m/embeddings/Add` ×2）→ 需重新接线。

- **性质说明（重要）**：这是**工作量上界估计，不是已验证的修法**。它只说明"要动的图结构有界"，
  **未证明**删掉这段就能消除 0 CPU 挂起——那仍是**假说**。最便宜的验证：
  造一份"掩码链由宿主 additive mask 取代"的 ONNX 变体，重跑 convert + benchmark，看挂起是否消失。
