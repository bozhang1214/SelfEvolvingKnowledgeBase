## 2026-09-21（M5 端口②：凭证端口搬进共享层 + iOS Keychain 实现；往返未验且原因明确）

- **背景**：iOS 要存设备凭证，而 Android 的 `CredentialStore` **接口**与 `CredentialCodec`
  （编解码）当时都留在 app 模块里——iOS 只能用不了或另写一套，那"四端同一套端口"就剩口号了。

- **改动**：
  - **搬进共享层**：`com.sekb.shared.device.CredentialStore`（接口 + `InMemoryCredentialStore`）
    与 `com.sekb.shared.device.CredentialCodec`；Android 侧只留 `KeystoreCredentialStore` 实现。
    两端从此共用**同一份编解码格式**，不会出现"Android 写的凭证 iOS 读不出来"。
  - `apps/ios/App/KeychainCredentialStore.swift`：`kSecClassGenericPassword` 实现该接口
    （upsert = 先删后写；`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`：仅本机、不同步 iCloud）。
  - iOS 自检改为**三态**（PASS/FAIL/**SKIP**，与 Android 自检同口径）：`CheckResult.ok` 改成 `Bool?`，
    "没验"不再伪装成过或失败。

- **验证（模拟器实测）**：`SEKB_IOS_SELFTEST PASS=16 FAIL=0 SKIP=1`
  - ✅ `keychain_empty_is_nil`、`keychain_clear`、`credential_rotation_rule`（共享层 `needsRotation`）
  - ⚠️ `keychain_roundtrip`：**SKIP**，原因 `OSStatus=-34018 (errSecMissingEntitlement)`
  - Android 侧：`bash scripts/android.sh test` → **231 全绿**（测试现在测的是共享层的 `CredentialCodec`）

- **硬结论（写进 `apps/ios/README.md`）**：模拟器上"手搓 `.app`"与"Keychain 可用"**互斥**——
  未签名 → `-34018`；`codesign -s - --entitlements ...`（哪怕只带 `application-identifier`）
  → SpringBoard 拒绝启动（`FBSOpenApplicationServiceErrorDomain code=1`）。
  当前选择保住"能启动"（其余自检都依赖它），Keychain 往返等真实 Xcode 工程 + 签名身份或真机时补验；
  `apps/ios/App/Sekb.entitlements` 已备好。

- **下一步（M5 端口③）**：嵌入（ONNX Runtime iOS / CoreML）——四个端口里最重的一个；
  之后让 iOS 自检项与 Android 对齐（16 vs 30）+ 同一标注集检索评测、数字一致。
