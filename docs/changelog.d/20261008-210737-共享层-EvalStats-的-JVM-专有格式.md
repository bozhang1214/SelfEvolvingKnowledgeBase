## 2026-10-08（共享层 `EvalStats` 藏着 JVM 专有 API：鸿蒙第一次编共享层时暴露；顺手把格式钉死）

- **背景**：这是**"真的把共享层编到第三端"才暴露出来的真缺陷**——不是猜的。
  鸿蒙 H1 第一次把 `apps/shared/src/commonMain` 编到 `ohosArm64` 时报：

  ```
  e: EvalStats.kt:43:43 Unresolved reference 'format'.
  ```

  原因：`EvalStats.formatRate` 里用了 **`"%.1f%%".format(...)`（Kotlin/JVM 专有）**，
  而它在 `commonMain` 里。也就是说 **iOS / Mac 的 framework 从来没编过这个文件**
  ——`-PsekbNativeTargets=true` 只在被显式打开时才声明 native target，而 iOS 侧一直只跑
  `scripts/ios.sh smoke` 那个不含 `EvalStats` 的子集。**"共享层零平台依赖"这句结论，
  在三端各自真的编过同一份源码之前，只对被测到的那部分成立。**

- **改动**：
  - `apps/shared/.../eval/EvalStats.kt`：改用共享层自己的 `Fmt.fixed(v, 1) + "%"`
    （同一文件集里已有，且 `FmtTest` 已钉住它与 `%.1f` 等价）。语义不变，只是不再依赖 JVM 格式化。
  - `apps/android/app/src/test/.../EvalStatsTest.kt`：新增 `formatRate keeps the exact JVM format`，
    把确切字符串钉死（`100.0% (95%CI 72.2%–100.0%, n=10)` / `0.0% (95%CI 0.0%–27.8%, n=10)`）。
    **为什么必须补**：原测试只断言 `contains("95%CI")`——**把实现改错也照样绿**
    （例如 locale 相关的逗号小数点会直接破坏报告与"同一张表"的跨端可比性）。

- **验证**：`bash scripts/android.sh test` → **292 用例 / 0 失败 / 0 跳过**（36 类，新增 1 条）；
  `apps/android/app/build/test-results/.../TEST-...EvalStatsTest.xml`：`tests="7" failures="0" errors="0"`，
  新用例确实执行并断言了确切字符串。
- **同步**：`fact:android_unit_cases` 291 → **292**（`apps/android/docs/VERIFICATION.md` 的权威行），
  并同步 `apps/android/README.md`、`docs/RFC-多端跨端方案.md`（3 处）、`docs/多端跨端-阶段汇总.md`（3 处）、
  `apps/README.md`（2 处）——**由 `scripts/check_edge_facts.py` 强制**（未同步则守卫变红，实测过）。
