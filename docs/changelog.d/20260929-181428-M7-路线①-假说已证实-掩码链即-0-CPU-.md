## 2026-09-25（**M7 路线① 假说已证实**：掩码链就是 0 CPU 挂起的成因，MindSpore Lite 实际可用）

- **结论（决定性）**：把静态 ONNX 里那段动态掩码展开链删掉后，模型**既能转换、也能运行**：
  ```
  CONVERT RESULT SUCCESS:0 → bge-nomask.ms 95,850,768 B、魔数 MSL2
  start unified benchmark run → PrepareTime = 148.073 ms
  Model = bge-nomask.ms, NumThreads = 2, AvgRunTime = 66.810 ms
  Run Benchmark bge-nomask.ms Success.        ← 不再是 0 CPU 挂起
  ```
  **即：跑不起来的根因是那段掩码链，不是 MindSpore Lite 缺算子。**

- **对 M7 路线判定的影响**：**① 可行** → 不必退回路线③（ArkTS 重写 + 契约夹具）。
  此前"Linux runtime 跑不起来 ⇒ 可能得放弃 MindSpore Lite"的倾向被推翻。

- **做法**（`scripts/model_to_ms_maskfree.py`，新增）：重接 4 处 `attention/self/Add` 的掩码输入
  → 全零常量，再做**迭代死代码消除** + 元数据清理（331→285 节点，清 38 个 initializer）。

- **两个坑都是报错直接指出的，不是猜的**：
  1. `SetMetaGraphInput] input Parameter_1 not found in graph` —— 掩码链是 `attention_mask` 的
     **唯一消费者**；删链后它成了"声明了但没人用"的死输入，转换器按内部名找不到就失败。
     修法：**同步裁掉无消费者的图输入**（语义自洽），而非加假消费者哄转换器。
  2. 只删节点不清元数据会留下陈旧 `value_info` 与未引用 `initializer`。

- **等价性（判据已修正）**：**关闭 ORT 图优化时两图逐位相同**；默认优化差 5.2e-06 属 ORT
  融合/调度噪声（上一轮已证实）。等价边界：全零掩码**只在无 padding 时严格等价**。

- ⚠️ **生产化仍差一步**：需把 additive mask 改成**模型输入**、由宿主按实际 padding 计算喂入
  （现在已证明这条路通，但还没做）。⚠️ 口径：66.8 ms 是 **Linux-aarch64 CPU** 数，
  **不是鸿蒙设备数**，鸿蒙真实性能仍须在模拟器/设备上测（M6 第 4 条）。
