## 2026-09-21（M4 第 2 步完成：依赖去平台化——4 个端口 + JSON 门面专测；202 测试全绿）

- **背景**：抽 KMP `shared/` 的前提是 `commonMain` 里不出现 JVM 专有 API。M4 第 2 步把散落在
  8 个文件里的 `org.json`、以及 `okhttp3` / `java.io.File` / `java.util.UUID` 全部收进端口。

- **改动**：
  - **`core/Json.kt`（新）**：`JsonObject` / `JsonArray` 门面，API 与 org.json 的**用到的子集同名**
    （`put` 链式、`opt*`、`get*`、`keys`、`length`、`toString`、`parse`），因此 8 个文件的调用点
    **只改 import**。org.json 从此只出现在这一个文件里。
    两处**有意的语义改进**：`parse()` 失败返回 `null` 而不是抛（网络响应不可信）；
    `optXxx` 必须给 fallback。
  - `net/OkHttpTransport.kt`：上一步已拆出（接口文件里不再有 okhttp 符号）。
  - **`core/PlatformFiles.kt`（新）**：`readText/readBytes/exists/isDirectory/listNames`；
    `BertWordPieceTokenizer` 改为吃**词表文本**（不再持 `File`），分词器因此成为纯 Kotlin。
  - **`core/Ids.kt`（新）**：`random()` / `short()`，`ChatOrchestrator` 不再直接用 `UUID`。
  - `ai.onnxruntime` **按设计留在** `embed/OnnxBgeEmbedding.kt`——它本来就是平台实现（接口是共享的）。

- **验证**：
  - `bash scripts/android.sh test` → **202 tests, 0 failed**（191 → 202：新增 `JsonFacadeTest` 11 条）。
  - `grep -rn "org.json" app/src/main` → **只剩 `core/Json.kt`**。
  - 重新统计可移植性（把 4 个端口文件算作平台）：**纯 Kotlin 3,723 / 5,673 = 66%**；
    `main` 里除这 4 个端口文件外**没有任何 JVM/platform import**。
    （之前 70% 的口径把端口文件也算进了"可移植"，已更正。）
  - 行为零变化：自检 27/27、检索评测数字不变（本轮未改逻辑，只搬依赖）。

- **新增测试守的三件事**（`JsonFacadeTest`）：① 坏输入必须返回 null 而非抛（半截 JSON、HTML 错误页）；
  ② 转义/中文/嵌套往返一致（手写 JSON 最容易死在这里）；③ 宽松读法给默认值、严格读法该抛就抛。
