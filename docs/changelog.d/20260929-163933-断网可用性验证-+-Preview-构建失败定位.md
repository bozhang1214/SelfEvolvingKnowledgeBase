## 2026-09-25（断网可用性验证通过；Preview 构建失败已定位；发现空间戳疑点）

- **断网可用性 ✅（真机飞行模式）**：开飞行模式 + USB `adb reverse` 保端侧可达，跑自检得
  **31 PASS / 0 FAIL / 1 SKIP**，与联网时**完全相同**（`edge_reachable` true、`rag_retrieve` 命中 0.690、
  隐私闸门 PASS）。即端侧嵌入/本地检索/隐私闸门/L1 策略**全不依赖互联网**。
  - **边界说清**：此处的"端侧"是**经 USB 直连宿主机的兼容端点**，不是"模型跑在手机 SoC 上"；
    本实验证明"链路不依赖互联网"，**不等于**验证了端侧推理运行时（那是 M6/M7）。
  - 实用技巧：自检输出全在 logcat，**不需要解锁屏幕**（锁屏会挡住截图）。

- **鸿蒙 Preview 构建：失败点已精确定位**（更正上一轮"卡住"的误判）：
  ```bash
  hvigorw --mode module -p module=entry@default -p product=default \
          -p requiredDeviceType=phone PreviewBuild --no-daemon
  # → 715ms 失败：ERROR: Failed :entry:default@PreviewArkTS
  #   The "data" argument must be of type string or an instance of Buffer... Received undefined
  ```
  即 hvigor 预览任务读了 IDE 才会注入的输入。
  - **两条自我更正**：① 上一轮以"10 分钟无输出"判定"卡住"是**错的**——真因是失败得很快，而我用
    `cmd | tail -40` 把输出**缓冲**住了（管道到结束才吐字节）→ **长任务不要管道给 `tail`，要写文件**；
    ② 修正后失败是**确定可复现**的，这才是可用信息。
  - **结论：优先走模拟器而不是继续钻 Preview CLI**。模拟器能验 **UI + 功能**（真 OHOS 能跑
    `libkn.so`/`.ms`），CLI 已完备，**只差 owner 下载镜像**；而 Preview 即使打通也**只能验 UI**
    （Previewer 是 macOS arm64，加载不了 ohosArm64 的 `libkn.so`）。
