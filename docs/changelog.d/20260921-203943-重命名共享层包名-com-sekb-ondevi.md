## 2026-09-21（重命名共享层包名：com.sekb.ondevice → com.sekb.shared）

- **背景**：owner 要求把共享层包名与模块职责对齐——`apps/shared` 里的代码不该再挂在
  `com.sekb.ondevice.*` 下（那会让"哪些是共享逻辑、哪些是 Android 专有"从包名上看不出来，
  开源后尤其别扭）。

- **改动**：
  - `apps/shared/src/{commonMain,androidMain,appleMain}/kotlin/com/sekb/ondevice/**`
    → `.../com/sekb/shared/**`；文件内 `package` 与互相 `import` 同步改名。
  - app 侧（main + test）：**按类型精确替换**受影响的引用（只改"确实搬到 shared 的类型"，
    避免误伤 app 自己的 `com.sekb.ondevice.*`）。
  - 同名包（app 的 `chat`/`net`/`rag`… 与 shared 的同名包）在 Kotlin 里不再自动可见 →
    给这些文件补了 `import com.sekb.shared.<pkg>.*`；平台实现（`OkHttpTransport`、
    `SqliteVectorStore`、`OnnxBgeEmbedding`、`AndroidDeviceTools`）额外补了显式 import
    （它们与共享接口原本同包，靠包内可见性"碰巧"编译得过，改名后暴露出来）。
  - 文档里指向旧路径的引用同步更新（`apps/android/app/.../route/PlaneRouter.kt` →
    `apps/shared/src/commonMain/kotlin/com/sekb/shared/route/PlaneRouter.kt` 等）。

- **验证**：
  - `bash scripts/android.sh test` → **207 tests, 0 failed**；
  - `-PsekbNativeTargets=true :shared:compileKotlinIosSimulatorArm64 :shared:compileKotlinMacosArm64`
    → **BUILD SUCCESSFUL**（改名没破坏 native 编译）；
  - `doc_guard.sh` **6/6 全绿**。

- **顺带发现**：改名把一处"隐性依赖"暴露了——app 的 4 个平台实现与共享接口原本同包，
  靠包内可见性编过；一旦分居两个包，就必须显式 import。这类"靠包名碰巧成立"的耦合，
  正是拆分时最该暴露的东西。
