## 2026-09-21（多端跨端方案 v0.1（iOS/鸿蒙/桌面）：待 owner 确认）

- **背景**：端侧目前只有 Android 一个端。要扩到 iOS / 鸿蒙，并回答"Windows/Linux 要不要做"，
  必须先定"哪些代码写一遍、哪些各写一遍、先做哪个"——否则每加一个端就是一次重写。
  另外两条前提变了：① CMP 1.9.3 已稳定且支持 AGP 9（我们 Android 侧正是 AGP 9.0.0）；
  ② 2026-06 HDC 华为发布 KMP/CMP 鸿蒙社区版 Beta（Kotlin/Native 新增 `OHOS_ARM64` target），
  `apps/harmony/README.md` 里"ArkTS 不能复用 Kotlin"的旧结论因此过期。

- **改动**（**只写方案，未动代码**）：
  - 新增 `docs/RFC-多端跨端方案.md`（draft）：五层架构（契约/纯逻辑/端口/UI/云端）、
    四个关键决策（D1 UI 统一 CMP、D2 鸿蒙走 KMP/CMP 社区版 + 3 天 spike、D3 桌面两步走、
    D4 各端推理运行时矩阵）、每个决策的**回退条件**、迁移路径 8 步（每步带可证伪验收）、
    一致性机制、里程碑与工作量、8 条风险、外部事实的本地待验清单。
  - 现状盘点（本仓库实测）：Android main 5,406 行 = **3,786 行（70%）不 import `android.*`** + 1,620 行平台代码；
    测试 2,274 行 / 182 用例。真正的跨端成本不是搬代码，而是把 4 类 JVM 依赖
    （`org.json` / `okhttp3` / `java.io.File`·`UUID`·`concurrent` / `ai.onnxruntime`）变成"端口"。
  - `apps/README.md`：分层表更新为四端共用一份；鸿蒙旧结论标注过期并指向新 RFC。
  - `apps/harmony/README.md` / `apps/ios/README.md`：加"前提已变"更新块（iOS 的 SwiftUI 计划降级为回退方案）。
  - `docs/README.md`：文档索引加一行。

  （仅 3 条 `org.json` 库名的"裸文件名"提示，非阻断）；`doc_guard.sh` 6/6 见同提交的运行结果。
