## 2026-10-26（鸿蒙 RDB `14800037` 根因定位并修复：`databaseDir` 的**父目录**不存在）

- **现象**（两个工作流都被它挡住）：`OH_Rdb_GetOrOpen` 报 `errCode=14800037`
  （`RDB_E_CREATE_FOLDER_FAIL`），表现为"新库名一律打不开、已存在的库偶尔能开"，
  于是 H5 的 `rag_*` 与 H8 的文档页都拿不到结论。三位协作者都试过修它，都没修掉。

- **根因（主线实测，证据在下面）**：
  真实 `databaseDir` = `/data/storage/el2/database/entry`，而 **`/data/storage/el2/database/` 整个不存在**
  （设备 `ls` 报 `No such file or directory`；`/data/storage/el2` 对 shell 不可见）。
  `fileIo.mkdirSync(dir)` **不创建中间目录** → 直接抛错；而 `OH_Rdb_GetOrOpen` 自己也不会建 →
  `14800037`。之前的诊断被两条东西盖住了：
  1. 日志只记了"父目录存在=false"，却把失败笼统写成"mkdir 未报错但仍不存在"；
  2. 目录在**某些轮次恰好存在**（例如刚被别的路径创建过），于是同一个库"有时能开" —— 看起来像间歇性故障。

- **改动**：`ets/model/AppCtx.ets` 的 `ensureDatabaseDir()` **先建父目录、再建目标目录**，
  两步各自记结果（`父=… 目标=…`），失败原因原样透出，不再退化成 RDB 的错误码。

- **验证（设备实测，一次性取全量 hilog 的方法也一并记下）**：
  ```
  $ hdc shell hilog -r ; hdc shell aa force-stop <bundle>
  $ hdc shell "aa start -a EntryAbility -b com.sekb.ohos.spike -m entry -A SEKB_SELFTEST"
  $ hdc shell hilog -x > /tmp/full-hilog.txt      # ⚠️ 先落盘再 grep（窄 grep 会漏行）
  ```
  ```
  SEKB_HARMONY_UI: RDB 目录自检：path=/data/storage/el2/database/entry 父目录存在=true 之前存在=true 之后存在=true mkdir=ok
  [PASS] rag_store_open — RDB 自检库已打开（隔离库，不碰用户的 sekb_docs.db）
  [FAIL] rag_ingest    — 导入「__selftest__」→ 列表里 1 篇（总片段 0 段）
  [FAIL] rag_retrieve  — 检索 → 0 条，首条=无（阈值=0.4）
  ```
  即 **`rag_store_open` 由 FAIL 转 PASS**，`rag_retrieve` 从"命中空 sourceId 的旧数据"变成"0 条"（库干净了，判据变准了）。

- **⚠️ 还剩一个真缺陷（已定位到"写入与读取不是同一份数据"，交给下一轮）**：
  `rag_ingest` 自检里 `rag_ingest_bridge`（`ing1.chunks >= 1`）通过、文档登记也成功（列表里 1 篇），
  但 `ragDocuments()` 显示 **总片段 0 段**，`ragRetrieve` 检索 **0 条** ——
  说明"切片写进去了、但读不到"。两个可能方向（按代价排序）：
  ① `SekbApp` 的**打开库**与**写入库**不是同一个实例/库名（`ragOpen` 的隔离库名 vs 界面库）；
  ② `RdbVectorStore` 的 `chunks` 表写入走了 `beginTransaction/commit`，而读取路径看不到未提交/被回滚的数据
     （F 的注释里记着 ValuesBucket 那条路在 Kotlin 侧不可用，写入改纯 SQL，事务语义值得复核）。
  判据已就绪：我加的 `rdbIdProbe`（`bash scripts/harmony.sh rdbid`，已接进 `SelfTestRunner`，
  自检项名 `rag_source_id_roundtrip`）会把"单列 SELECT / 多列 SELECT / 生产 all() / deleteBySource / 维度校验"
  分五层报出来，哪一层坏一眼可见 —— 本轮它在两条运行里都没来得及落进日志缓冲，**没拿到明细**，如实记为未验。
