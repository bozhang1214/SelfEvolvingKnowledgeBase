### 做了什么

**① 绑定来源（省掉一整轮返工的关键发现）**
OHOS Kotlin fork 的**平台 klib 已内置** ArkData/RDB 绑定：
`klib/platform/ohos_arm64/org.jetbrains.kotlin.native.platform.RDB`，manifest 自带
`headers=database/rdb/relational_store.h` + `linkerOpts=-lnative_rdb_ndk.z`，包名 `platform.ArkData.RDB`。
→ **不需要自建 cinterop `.def`**（第一版按 `ohcrypto.def` 的先例白写了一份，已删）。
`llvm-readelf -d libkn.so` 实测 `DT_NEEDED` 里出现 `libnative_rdb_ndk.z.so`。

**② RDB 可用性探针（HR2 的"最小验证先于完整实现"）—— 设备原始证据**
`bash scripts/harmony.sh rdbprobe`（127.0.0.1:5555）：
```
LOAD OK   libnative_rdb_ndk.z.so
SYMBOLS OK  10 个符号全部解析（含 GetOrOpen/Execute/Insert/ExecuteQuery/CloseStore）
CONFIG SIZE sizeof(OH_Rdb_Config)=45（期望 45 = 4+8*4+1+4+4，pack(1)）
OPEN OK   errCode=0 dir=/data/storage/el2/database/entry
EXECUTE   rc=0
PUT       text=0/0/0 int64=0 blob=0
INSERT    rowId=1
QUERY     rows=1 id=probe#0 dim=3 text=端侧 RAG 探针文本
BLOB      12B 读出后逐字节相同=true
REOPEN    close=0 reopen_err=0 行数=1
RDB-DLOPEN PASS
```
这条走的是 **C++ dlopen + dlsym**（不依赖链接期），与 Kotlin 侧平台 klib 是**两条独立判据**。

**③ 新增文件**（`apps/harmony/spike/knspike/src/ohosMain/kotlin/`）
- `RdbStore.kt`：config/句柄/Cursor 读值/BLOB 编解码。含三条**实测**的 cinterop 坑：
  结构体里的函数指针**没有 `@CCall` 转换**（传 `String` 编译不过、`reinterpret` 也绕不过），
  必须自己准备 C 缓冲；`CPointer<CFunction<…>>` 调用需要**显式 `import kotlinx.cinterop.invoke`**
  （否则报一组"类型无法推断/receiver 不匹配"的误导性错误）。
- `RdbVectorStore.kt`：`VectorStore` + `DocumentRegistry`，语义与 Android `SqliteVectorStore`
  **逐条对齐**（表结构/列名、小端 float32 BLOB、`CONFLICT_REPLACE` 的 upsert、
  "维度不符"同一条消息、`deleteBySource` 返回删除条数、暴力余弦 + `VectorMath.topK`、
  `clear` 连文档元信息一起清、`list()` 走 SQL `ORDER BY added_at DESC`）。
- `RdbProbe.kt`：HR2 探针（建表/插入含 BLOB/查询往返/**关闭重开仍可读**），
  并与 `RdbVectorStore` 共用同一套读法。
- `RagSelfTest.kt`：5 条 `rag_*` 自检（ingest / retrieve / delete 不误伤 / threshold_refuses /
  device_only_gate）+ 反向验证 + **检索评测同表**（复用共享层 `RetrievalEvalSet`/`RetrievalEvalRunner`，
  索引换成 RDB 持久化实现）。

**④ 接线**：`scripts/harmony.sh` 新增 `rdbprobe` / `rag` 两个动作；`Index.ets` 串行追加。
