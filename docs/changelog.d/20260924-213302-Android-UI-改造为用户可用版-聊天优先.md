## 2026-09-24（Android UI 改造为用户可用版：聊天优先、配置收进设置、新增 Markdown 渲染）

- **背景**：owner 指出 Android 版界面仍是"调试 UI"，要求优化为**用户可用**的界面并参考网页端。
  截图确认属实：裸 URL、裸设备 ID、原始文档名（`doc-rag (1 段, 36B)`）、端点/账号密码输入框、
  审计与工具合法率统计**全铺在聊天首页**——用户第一眼看到的是配置项与内部指标。

- **改动**（全部在 UI 层，未动共享逻辑与协议）：
  - **拆成三个页面**：聊天（首页）/ 本机知识库 / 设置。用一个 `enum` + `when` 的极简导航壳
    （不引 navigation-compose：只有三个扁平页面，没有深链接与回退栈需求），
    并用 `BackHandler` 让子页面正确响应系统返回键。
  - **新增 `ui/theme/SekbTheme.kt`**：主色对齐网页端 Ant Design 的蓝 `#1677ff`（原为 M3 默认紫），
    定义**语义色**——绿 = 本机完成、金 = 已上云（只在执行位置徽章上用，避免"绿色"失去含义）。
  - **首页不再出现任何 URL**：状态改成一句话 + 圆点（"端侧就绪 · 数据不出本机" /
    "端侧不可用 · 将使用云端"）。**执行位置徽章保留但弱化**——它是产品承诺（设备专属数据不出端），
    不是调试信息，所以每条回答都要标。引用来源默认收起为"引用 N 段本机资料"，可展开看出处与分数。
  - **报错/提示改走 Snackbar**，不再在输入框上方堆小字。
  - **空状态**：头像 + 说明 + **三个真的问得出来的示例问题**（对应端侧知识、本机知识库、设备工具），
    点了会填进输入框，让用户立刻有一次成功体验。
  - **新增 Markdown 渲染**（`ui/Markdown.kt` + `ui/MarkdownView.kt`）：模型回答本来就是 Markdown，
    此前直接 `Text(bubble.text)` = 让用户读源码，而网页端是渲染的。自己实现（不引第三方库，
    理由同 `BertWordPieceTokenizer`），覆盖标题/列表/有序列表/引用/代码块/表格/分隔线 +
    行内粗体/码/斜体/链接。两条硬约束都有单测：**流式前缀不丢字**、**解析器不抛异常**。
  - **`scripts/android.sh` 新增 `install-real`**：华为真机 `adb install` 会连着弹两层确认
    （系统「风险提示 → 继续安装」，再交给「华为应用市场」风险检测，且**必须先勾"已了解…"确认框**），
    不点就一直挂着。脚本用 `uiautomator dump` **按按钮文字反查坐标**（硬编码坐标换机型就废）
    自动越过；并处理了 `ADB_BIN` 解析失败（`find` 不跟随软链接 → 空字符串 → `: command not found`）。

- **验证**：
  - `bash scripts/android.sh test` → **244 用例 / 0 失败**（新增 13 条 `MarkdownTest`，含逐字符流式前缀不丢字）。
  - **真机截图逐页核对**（Mate 40 Pro）：聊天空状态、真实问答（Markdown 标题/项目符号/代码块/
    分隔线渲染正确 + 执行位置徽章 + 流式提示）、本机知识库、设置四个分组卡片。
  - 过程中修掉一个**只有装到真机才看得见**的 bug：空状态用 `fillMaxSize()` 会在 Column 里吃掉全部高度，
    把**底部输入栏挤出屏幕**（整屏只有空状态、无法输入）→ 改为 `weight(1f)`。
  - 证据与取舍记入 `apps/android/docs/VERIFICATION.md` §1.2。
