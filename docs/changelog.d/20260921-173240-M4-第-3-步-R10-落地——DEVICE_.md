## 2026-09-21（M4 第 3 步：R10 落地——DEVICE_ONLY 的「本机」判据（代码 + 测试 + 夹具））

- **背景**：`DEVICE_ONLY` 的语义是"永不离开本设备"，但 LLM 平面的 EDGE 只按 `edgeBaseUrl` 寻址——
  这个地址**可能是另一台机器**（Android 模拟器里就是 `10.0.2.2` = 开发机）。嵌入侧早有
  `EmbeddingProvider.isOnDevice` 闸门，LLM 侧没有 → 标记"永不出设备"的数据实际会发到开发机。
  这条是桌面审计提出、并被记为本期 M4 必做的 **R10**。

- **改动（代码）**：
  - `model/Models.kt`：`RouteDecision` 新增 `blockedReason: String?` 与 `isBlocked()`——
    非 null 表示**一个请求都不许发**（既不端侧也不云端）。
  - `route/PlaneRouter.kt`：新增 `isLocalEndpoint()` / `hostOf()`（纯字符串解析，为 KMP 铺路，
    不引 `java.net.URI`）。判据**保守**：只有回环地址（`127.0.0.1` / `localhost` / `[::1]` /
    `localhost.localdomain`）算本机；域名、`0.0.0.0`、局域网、尾网一律**非本机**。
    DEVICE_ONLY + 非本机端点 → `reason=blockedReason=device_only_requires_local_runtime`。
  - `chat/ChatOrchestrator.kt`：决策被拦时**直接返回**（端侧 0 次、云端 0 次调用），
    上报一条 `escalation_blocked:device_only_requires_local_runtime` 留痕，并把原因作为可读 error 交给用户。

- **改动（测试与夹具）**：
  - `PlaneRouterTest`：4 条新测试——非本机必须被拦；局域网/尾网/域名/`0.0.0.0` 都算非本机；
    `127.0.0.1`/`localhost`/`[::1]` 算本机；**普通数据打远端端点不受影响**（不误伤端云协同）。
  - `ChatOrchestratorTest`：新测试钉住"端侧 0 次、云端 0 次、text 为空、error 可读"；
    原 DEVICE_ONLY 测试改用**本机**端点（它要验的是"升级被隐私边界拦下"，需要端侧真的能跑）。
  - `apps/contract/privacy.json` 8 → **13 case**：本机可执行 / 局域网被拦 / **模拟器宿主 `10.0.2.2` 被拦** /
    尾网被拦 / 普通数据对照组；runner 支持 `edgeBaseUrl` 覆盖与 `blocked`/`expectReason` 断言。

- **验证**：`bash scripts/android.sh test` → **191 tests, 0 failed**（功能 187 + 契约 4）。
  期间夹具两次抓到我写错的地方（"被拦的 case 不该要求命中升级信号"），已按语义修正断言。

- **⚠️ 行为变化（要记住）**：模拟器上 `edgeBaseUrl=10.0.2.2` → **DEVICE_ONLY 请求会被明确拒绝**，
  不再发给开发机上的 Ollama。这是隐私边界的正确语义（"本机"≠"局域网里的另一台机器"）；
  真机接入本地运行时后才有可用的 DEVICE_ONLY 端侧推理。已写进 `apps/android/docs/VERIFICATION.md` §1.0。
