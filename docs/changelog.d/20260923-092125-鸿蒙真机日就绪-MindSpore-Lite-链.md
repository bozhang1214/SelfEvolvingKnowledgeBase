## 2026-09-23（鸿蒙真机日就绪：MindSpore Lite 链路接到 App，装包即出结果）

- **背景**：鸿蒙真机调试顺延到次日。本轮把"真机日要做的事"**提前做完**，
  目标是让明天只需要**装包 + 看屏幕**，而不是现场写代码、现场查 API。
  这也直接决定了 M7 的路线（模型能跑 → MindSpore Lite；不能跑 → 立刻转路线③）。

- **改动**：
  - 新增 `apps/harmony/spike/knspike/src/ohosMain/kotlin/MsLite.kt`：MindSpore Lite C API 的薄封装
    （`MsSession`：建 context/model、按输入名喂数据、predict、读回 float），**只依赖平台 klib、不依赖共享层**。
    两个实测要点写进注释：**按值返回的结构体在 cinterop 里是 `CValue<T>`**（必须 `useContents`，
    直接赋值会报 `Initializer type mismatch ... actual 'CValue<OH_AI_TensorHandleArray>'`）；
    C 枚举/状态码是 **`UInt`**（与 `0u` 比），数据类型真名是 `OH_AI_DATATYPE_NUMBERTYPE_INT64`（**不是** `..._INT64`）。
  - `MindSporeProbe.kt` 重写为两个**真机日入口**：`sekb_spike_mindspore_selftest`（成功返回输出元素数、
    失败返回可区分步骤码 `MsStep`）与 `sekb_spike_mindspore_first_float`（`|v[0]|×1e6`）。
    第二个是必要的：元素数只能证明"形状对"，**全零也能通过**；首元素非零才证明数据真的流过来了。
  - `napi_init.cpp` 暴露 `msSelfTest` / `msFirstFloat`；`pages/Index.ets` 启动时把 `.ms` 从 rawfile
    复制到应用私有目录并展示三行结果（含"失败步骤码 → 含义"对照）。
  - `scripts/harmony_spike.sh`：`hap` 会把 `.ms` 放进 `entry/src/main/resources/rawfile/`
    （`OH_AI_ModelBuildFromFile` 要**文件系统路径**，rawfile 不是路径）→ **真机日不需要手工 push**；
    校验从"2 个 KMP 符号"加强到 **4 个**（否则校验比真实依赖弱，漏接一个也发现不了）+ 断言模型在包内；
    并修掉一句已过期的提示（它还写着"本机没有 converter_lite"）。
  - `MindSporeBgeEmbedding.kt`（完整 `EmbeddingProvider` 实现，CLS pooling + L2 + 空间戳）
    移到 **`kotlin-pending/`（不参与编译）**：接进来需要先给 `ohosMain` 补共享层 `actual` 端口
    （`Clock`/`Hmac`/`Digests`），属于 M7 的活；**先确认模型能跑再付这个成本**，
    否则一旦转路线③这份 Kotlin 就白写。
  - `apps/harmony/README.md` 新增「🎯 真机日操作清单」：链路图 + 三行结果的读法 + 步骤码对照表。
