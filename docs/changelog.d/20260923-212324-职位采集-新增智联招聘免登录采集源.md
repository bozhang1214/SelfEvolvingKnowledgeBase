## 2026-09-23（职位采集：新增智联招聘免登录采集源）

- **背景**：早前 `docs/ops/10-JOB-SOURCES.md` 对智联的结论是「**无免登录接口** → 走浏览器插件」
  （依据：接口返回 200 但 `results:[]` 恒空）。该结论**只测了旧接口层，是错的**，导致智联一直
  没进采集源——FDE 全量扩搜时它 0 产出。
  服务器实测复核后确认：**智联搜索页免登录完全可用**（只有 `/recommend` 需登录）。

  复核中发现并修正了三处误判：
  1. **URL 形式**：必须**城市码放 `jl` 路径段、裸关键词放 `kw` query**
     （`/sou/jl530/?kw=<URL编码关键词>`）。早前记的 `?kw=…&city=530`（城市放 query）是退化形式，
     会掉到通用页并混入外地岗——那个「命中率 2/20」的误判就是它造成的，**不是智联不支持中文/免登录**。
  2. **关键词编码**：站点会**自己完成编码并 302**（`FDE`→`kw01300H008K`、`前沿部署`→`kwA96MPFSGT1VN4`），
     调用方不需要知道编码规则，**中文关键词同样可用**。
  3. **卡片选择器全部过期**：早前记的 `.jname`/`.cname`/`.sal` 实测 **0 命中**，
     真实为 `.jobinfo__name` / `.companyinfo__name` / `.jobinfo__salary` / `.jobinfo__other-info-item span`。

- **改动**：
  - `browser-service/app.py`：
    · 新增 `@_register_scraper("zhaopin")` 的 `_scrape_zhaopin()`——按上述 URL 形式打开搜索页，
      等卡片渲染后按新选择器抽取（title / company / salary / city / job_url / job_id），
      并抽出 `_card_text()` 辅助函数；
    · 新增 `ZHAOPIN_CITY_CODES`，**只收录实测验证过的 `北京=530`**。未收录城市**直接跳过并记日志**，
      因为去掉 `jl` 段会退化成通用页混入外地岗——静默采错城市比采不到更糟。
      文件内写明了复验方法，以及实测无效的 11 个候选码。
    · 新增 `import re` / `from urllib.parse import quote`。
  - `backend/app/agents/job/collector.py`：把 `BossBrowserSource` 抽成 `_BrowserSource` 基类
    （子类只给 `name`/`site`），新增 `ZhaopinBrowserSource`（`site="zhaopin"`）并注册进
    `_load_sources()`；`_safe_fetch` 的 `isinstance` 判断改指向基类。HTTP 超时 60s → 90s
    （浏览器要启动 Chromium + 导航 + 等渲染，比普通 HTTP 源慢一个量级）。
  - `backend/tests/unit/test_job_collector.py`：新增 7 个用例（23 passed）——两个源的
    `site`/`name` 配置与共用基类、智联 POST 的 `site=zhaopin` 且补 `source`、BOSS 仍发 `site=boss`、
    空关键词不发请求、非 200 静默降级、异常静默降级、`_load_sources()` 同时注册两站。

- **验证**：
  - `ruff check app/ tests/` 通过；`bash scripts/mypy_gate.sh` → 300 ≤ 基线 310，无新增类型错误。
  - `pytest tests/unit/test_job_collector.py` → **23 passed**（新增 7 个）。
    本次改动相关的 5 个测试文件合计 **67 passed**。
  - `pytest tests/unit`（排除 `test_short_term_memory.py` 与 `test_p0_fixes.py`）→ **949 passed**。
  - ⚠️ **本地全量跑不绿，原因是沙箱环境，与本次改动无关**：`tiktoken` 需要从
    `openaipublic.blob.core.windows.net` 下载 `cl100k_base` 编码文件，而该域名在当前沙箱内
    **DNS 解析失败**（`Temporary failure in name resolution`；同容器内 `pypi.org`、
    `mirrors.cloud.tencent.com` 均正常解析，且镜像内无 tiktoken 缓存可指定）。
    受影响的是 `test_short_term_memory.py`、`test_p0_fixes.py::TestCompressAtomicity`、
    `test_storage_memory_integration.py` 共 28 failed + 5 errors——**全部报同一个
    `SEKBMemoError: tiktoken 编码加载失败`**。CI 跑在 GitHub runner 上可访问该域名，不受影响。
  - 服务器实测（`sekb-browser` 容器内、零 Cookie）：
    `/sou/jl530/?kw=前沿部署` → 302 到 `/sou/jl530/kwA96MPFSGT1VN4/p1`，20 张卡片，
    卡片城市**全部为「北京·xx」**，页面标题为「2026年**北京**前沿部署招聘信息」；
    首条即「FDE前沿科技部署工程师-企业直签-Agent 大模型方向」。

- **已知边界（诚实说明，均写进 `docs/ops/10-JOB-SOURCES.md`）**：
  1. **分页未解**：把重定向后的 `/p1` 改成 `/p2` 实测 0 卡片（被打回通用页），
     需点击分页控件或找对参数 —— **上限 20 条/关键词**；
  2. **城市码只支持北京**：`jl` 码不是通用城市码，实测 11 个候选全部 0 卡片；
     城市落地页里出现的码是共享导航链接，不可用。另注：服务器 IP 在北京，站点**可能按 IP 定位**，
     `jl=530` 未必真在过滤——但采到的结果确实是北京；
  3. **JD 正文为空**：经典页卡片不含职位描述，`jd_text` 留空（进详情页会显著变慢）；
  4. 新版页面另有明文 JSON 接口 `POST fe-api.zhaopin.com/c/i/search/positions`
     （响应 `{count:100,list:[…]}`，字段齐全），但请求体是签名 blob 且按 URL 直达不触发，
     暂作为抗改版的备选方案记录在案。
