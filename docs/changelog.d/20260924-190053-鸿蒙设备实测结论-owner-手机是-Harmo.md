## 2026-09-23（鸿蒙设备实测结论：owner 手机是 HarmonyOS 4.2（非 NEXT），无法验收 HAP）

- **背景**：owner 的手机已连上 MacBook，但 DevEco 设备列表始终为空。查清原因，避免在错误方向上
  继续投入（换线/换口/改配置都不会有用）。

- **实测证据（决定性）**：
  | 检查 | 结果 |
  |---|---|
  | `adb devices` | ✅ 能看到 `PQY0221B17004077 product:NOH-AN00` —— **说明 USB 层已通**（换线 + 去掉 Hub 起了作用） |
  | `hdc list targets` | ❌ 恒为 `[Empty]`（即使 hdc 服务是 DevEco 自己拉起的、不受我方沙箱限制） |
  | `hw_sc.build.platform.version` | `4.2.0` → **HarmonyOS 4.2** |
  | `ro.build.version.release` / `emui` | `12`（Android 12） / `EmotionUI_14.2.0` |
  | **`const.ohos.apiversion`** | **空** → **不是纯血鸿蒙（HarmonyOS NEXT）** |

- **结论**：`hdc` 只与 **HarmonyOS NEXT** 设备通信；HarmonyOS 4.x 是 AOSP 基座、对外暴露 **ADB**。
  所以"DevEco 看不到设备"与 MacBook / 数据线 / Hub / DevEco 都无关。
  **⚠️ 更重要的影响**：本项目 HAP 目标是 **API 22 / HarmonyOS 6.0.2（NEXT 世代）**，
  **装不到 HarmonyOS 4.2 上** → M6 spike 第 4 条（HAP 能装能起）**无法用这台手机验收**，
  不是"再调一下就行"。

- **改动**：`docs/RFC-多端跨端方案.md` §10 —— E13 改写为该实测结论（并去掉已被推翻的
  "hdc/adb 都看不到手机"表述）；签名材料现状独立为 E13b。

- **验证**：`adb devices` 与 `getprop` 均为真机实测输出；`hdc list targets` 在
  DevEco 自有 hdc 服务（PID 由 DevEco 拉起）下复测仍为空。

- **下一步（需 owner 决定）**：① 换 **HarmonyOS NEXT 设备**（Mate 60/70、Pura 70、nova 12+ 等）
  验收真实机；② 或**用 DevEco 模拟器镜像**（Device Manager 下载；本机目前无任何镜像）。
  两者都不影响已经就绪的东西：HAP 与 `.ms` 已打好（96M）、真机日入口已接到界面上，
  设备一到就是"装包 + 看三行字"。**签名那一步不需要手机**，可以先点掉。
