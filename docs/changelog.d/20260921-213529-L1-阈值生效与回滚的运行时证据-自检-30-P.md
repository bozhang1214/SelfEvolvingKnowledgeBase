## 2026-09-21（L1 阈值生效与回滚的运行时证据 + 自检"测量卫生"修复）

- **背景**：L1 的纯逻辑（`EdgePolicy`）与拉取器都已验过，但"策略改阈值是否**真的**生效"只有
  单测级证据；而 `minScore` 是构造参数、`KbSearchTool` 又抓住检索器实例——这正是
  最容易"看起来改了、实际没生效"的地方，必须有运行时证据。

- **改动**：
  - `AppContainer`：抽出 `applyAppliedConfig()`；新增 **仅供自检** 的 `debugApplyPolicy()`（离线应用注入
    的策略，不联网）与 `debugResetPolicy()`（清存储 + 按默认 0.5 重建）；`retriever`/`tools` 改为
    可一同重建（`buildTools()`），并在策略应用后调 `applyPolicyToRuntime()`（阈值没变则不动）。
  - `Retriever.minScore` 公开只读（自检才能断言"阈值真的进去了"）。
  - `scripts/android.sh` 新增 `push-policy <file>`：把已签名策略推进 app 私有目录
    （intent 传 JSON 不可靠——实测被 `am` 重新解析成 `dat=issuedAt:`）。
  - 自检：策略检查**挪到整轮最后**并自清理；`edge_reachable=false` 改为**非致命**。

- **验证（模拟器实测）**：
  ```
  [PASS] policy_apply_rebuild — 应用=777 阈值 0.5 → 0.7（期望 0.7）重建=true
  [PASS] policy_threshold_wired — 检索器阈值=0.7（策略=0.7）
  [PASS] policy_rollback_restores_threshold — 先应用到 0.9，回滚后阈值=0.7
  [PASS] rag_retrieve — 命中=doc-rag 分=0.690
  自检汇总：PASS=30 FAIL=0 SKIP=2
  ```
  `bash scripts/android.sh test` → 231 测试全绿；`doc_guard` 6/6。

- **过程中暴露并修掉的两个真问题（值得记）**：
  1. **自检的注入策略污染了后续检查**：策略块原本在 RAG 项之前，阈值抬到 0.7 后
     `rag_retrieve`(0.690)/`rag_tool_search`(0.645) 全 FAIL——**测量工具不能在测量前改变被测对象**。
     修法：策略检查放最后 + 结束后 `debugResetPolicy()`。
  2. **端点不可达会中断整个自检**：早期 `if (!reachable) return items` 让"宿主 Ollama 没起"
     变成"自检只剩一条"，本地项（RAG/策略/权限）全被掩盖。改为记录 FAIL 但继续。
