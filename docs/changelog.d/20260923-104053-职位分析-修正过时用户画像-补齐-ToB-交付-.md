## 2026-09-23（职位分析：修正过时用户画像（补齐 ToB 交付 + SEKB + 端侧））

- **背景**：`prompt/job/README.md` 的 `user_profile` 段是所有职位分析提示词
  （`{{user_profile}}`）的唯一注入源，但它标注为「从 `resume/张博-技术经理.pdf` 提炼」——
  那是**转型前**的技术经理简历。由此产生三个偏差，让职位分析**系统性低估候选人**：
  ① 漏掉「3 年运营商 ToB 方案与客户交付」（FDE/售前方向最核心的匹配点）；
  ② 把 `LangGraph/LangChain/RAG/LLM 应用后端/Python/MCP` 列为 `weak`，而这些**全部已由
  SEKB 项目落地**（五 Agent 编排 + 混合检索 RAG + MCP 内核化 + FastAPI/SSE + 909 测试 + 线上部署）；
  ③ `target_role` 未包含 FDE / 解决方案 / 售前。
  实测影响：同一批 49 个 FDE 职位、同一套提示词，仅改画像，结论从
  「需补齐 Python+LangGraph+RAG 动手项目（2-3 个月）」变为
  「真实水位对标『10 年+3 年 AI』的专家岗」，谈薪口径从「底线 50k×14」升至「55K×14，天花板 80-110K×15」。

- **改动**：
  - `prompt/job/README.md`：重写 `user_profile` 段——补上运营商 ToB 交付
    （50+ 客户 / 亿级营收 / 唯一对外接口人 / 方案规范沉淀）、补上 SEKB 与 Android 端侧 Agent；
    `skill_stack` 三段重构（`weak` 改为**底层推理优化 / 模型训练 / 垂直行业 know-how**）；
    `target_role` 加入 FDE；`min_salary` 保持**不给具体数字**（`"面议（不低于上一份）"`）。
    并显式加注释：**本文件在公开仓库中，禁止写入真实上一份薪资、具体数字底线或联系方式**
    （修订过程中曾把「上一份 55K×14 ≈ 77 万」写进注释，等于公开自己的谈薪锚，已改掉；
    具体数字锚定改走**不入库**的按用户画像 `min_salary_k`）。
  - `backend/app/agents/job/profile.py`：`_FALLBACK_PROFILE` 同步更新——README 缺失时的兜底画像
    不能又是旧版，否则同样的低估会以「静默回退」的形式复现。
  - `backend/tests/unit/test_job_profile.py`（新增，5 个用例）：回归门禁——README 必须可解析且非回退、
    必需字段齐全、`weak` 中**不得再出现 LangGraph/RAG/MCP/Python**、必须含「交付/运营商/SEKB」且
    `target_role` 含 FDE；兜底画像同样要可解析且含交付经历；
    **防泄露门禁** `test_profile_readme_does_not_leak_salary_numbers`——
    `min_salary` 不得含数字（公开文件不放谈薪锚）；
    **单方向门禁** `test_target_role_is_a_single_direction`——
    `target_role` 不得并列多个方向（简历按方向定制，多方向并列会让每次分析的目标被稀释）。
  - `prompt/job/README.md` 第二轮（用户逐项确认后）：
    · `target_role` 从「FDE · 端侧 Agent · 平台架构 · 售前」四个方向并列收窄为**单一主方向**
      `AI Agent 解决方案与交付（FDE）`——其余方向由「搜索关键词 + 按方向定制的简历版本」承载；

      爱奇艺任期内**（2019-2021）——原表述与「爱奇艺 10 年」并列，面试时会被误读成额外 3 年、造成时间线矛盾；

    画像更新后旧分析自动失效，不会返回基于旧画像的静默错误结果。

- **⚠️ 归因更正（事后核实）**：上述「报告转向」**不是本次 README 修改带来的**。
  核实线上后发现：容器 `prompt` 目录是 bind mount
  （`/opt/self-evolving-kb/SelfEvolvingKnowledgeBase/prompt → /app/prompt`），
  服务器 checkout 的 `prompt/job/README.md` **仍是旧版**，本次改动**尚未部署**。
  真正起作用的是**按用户画像补充**那一层——`load_user_profile(user_id)` 会把
  `data/profile/{user_id}.json` 渲染成「【用户实时更新偏好】」追加在基础画像之后，
  本次一并更新了该文件（`bio` 写入「运营商 ToB 方案与客户交付」、`skills` 写入
  Agent 工程化/RAG 工程、`target_roles` 加入 FDE、`min_salary_k=55`），
  **它把过时基础画像里的 `weak` 覆盖掉了**，于是报告转向。
  两点结论：① 私有补充层可以单独纠正基础画像的偏差，且改它无需部署；
  ② 但线上提示词当前**自相矛盾**（基础画像说 weak、补充文本说是强项），
  本次 LLM 恰好倒向后者，属不稳定巧合——**需 push + `deploy/deploy.sh`
  让基础画像与补充文本一致**。
