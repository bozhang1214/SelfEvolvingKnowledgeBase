## 2026-09-18（内核 MCP 建连改用 asyncio.timeout（wait_for 跨 task））

- **背景**：上一条把「CLI 退出时泄漏内核 MCP」修好后（traceback 消失、`stdio_client`
  不再被生成器终结器收尾），部署实测发现**还剩一条 warning**：

  ```
  {"error": "Attempted to exit cancel scope in a different task than it was entered in",
   "event": "MCP 资源清理异常", "level": "warning"}
  ```

  根因在**建连**一侧：`JobCopilotMCP._ensure_client` 用
  `asyncio.wait_for(client.connect(), timeout=...)` 包住建连，而 **wait_for 会把协程放进
  新 task 里跑**（实测：`wait_for` 里 `current_task()` 与调用方不同，`asyncio.timeout` 则相同）。
  MCPClient 内部的 `stdio_client` / `ClientSession` 是 anyio 的 cancel scope，
  要求「进入」「退出」同一个 task —— 建连在子 task 里完成，关闭就必然报跨 task，
  子进程也得不到干净回收。

- **改动**：`backend/app/agents/job/mcp_client.py` 改为 `async with asyncio.timeout(...)`
  包住建连（在当前 task 里取消，语义等价、超时仍转成 `KernelMCPError`），
  并在 `_build_client` 的注释里写明「不能用 wait_for」，避免有人再改回去。
  Python 版本要求 `>=3.11`，`asyncio.timeout` 可用。

- **验证**：
  - 新增回归测试 `test_connect_runs_in_caller_task`：用假 MCPClient 记录 `current_task()`，
    断言建连与调用方**同一个 task**（旧写法必红）。
  - A/B 实测：`asyncio.wait_for` → 同一 task? **False**；`asyncio.timeout` → **True**。
  - `pytest tests/unit` → **950 passed**；ruff 全过；mypy 308 ≤ 基线 310。
