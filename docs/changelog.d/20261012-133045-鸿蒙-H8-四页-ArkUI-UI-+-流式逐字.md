## 2026-10-12（鸿蒙 H8：四页 ArkUI UI + 流式逐字/徽章/来源 + SEKB_HARMONY_SELFTEST 自检表）

- **背景**：鸿蒙端此前只有"自检骨架页"（`pages/Index.ets`）与一个与 NAPI 零连接的
  `pages/Chat.ets` 骨架；方案《多端跨端-鸿蒙端方案》**H8** 要求的四页应用 + 导航 +
  流式逐字 + 自检表一直没有落地，端侧 Agent 的主界面（聊天）用户看不到。

- **改动**：
  - **四页 + 导航**（`pages/AppShell.ets` + `ChatPage/HistoryPage/DocumentsPage/SettingsPage`，
    与 Android `SekbScreen` 同名同序；一个 `screen` 状态 + 顶栏返回，**不引路由框架**）。
    `EntryAbility` 改为加载 `pages/AppShell`；`pages/Index`（H1–H6 自检面板）**一行未改**、仍注册。
  - **聊天页真接线**：ArkTS 只搬字节（`model/ChatTransport.ets`：`@ohos.net.http` + 按 `\n` 切行），
    **每个完整行同步调 `chatStreamLine`**，SSE 语义由**共享层 `SseParser`** 决定；
    正文逐段回传后逐字渲染（实测一轮 `code=200 bytes=76343 textChars=632`、361 个 token 事件 + done）。
    执行位置徽章（本机=绿/云端=金）、原因码经共享层口径 `explainReason` 渲染（认不出的原样透出）、
    检索来源列表、空状态示例问题、底部输入栏。
  - **历史页真落盘**：JSON 文件 + **先写 `.tmp` 再 rename** 的原子替换（`model/HistoryStore.ets`）；
    支持切换/删除/新对话。**不依赖 RDB**（RDB 挂了也不该把聊天记录带走）。
  - **文档页**：导入（`.txt/.md/.markdown`；PDF 明确后置）、列表（名称/片段数/体积）、
    **单篇删除走共享层 `KnowledgeIndex.remove`**（不误清全库），删除后**回读核对**剩余篇数。
  - **设置页**：设备身份（**如实显示"未接入"并禁用 enroll/refresh**）、检索阈值默认 **0.40**
    （设置页与共享层同值，非法值回落）、端侧嵌入状态（模型/空间戳/维度）、网络与后端地址、
    **自检入口 + `SEKB_HARMONY_SELFTEST` 表**、版本信息。
  - **NAPI**：新增 `entry/src/main/cpp/sekb_chat_napi.cpp`（14 个入口：`chatRoute/chatStream*/rag*`），
    在 `h3h4_napi.cpp` 末尾**加一行**挂载；`napi_init.cpp`（主线独占）**一行未动**。
    Kotlin 侧新增 `ChatStreamPort.kt` / `SekbAppPort.kt`（**只做胶水**，语义全在共享层）。
  - **主题集中**：`model/Theme.ets` 是唯一色值来源（主色 `#1677FF`、底 `#F5F7FA`、白卡片、圆角），
    页面里不出现 `'#RRGGBB'`（Android 曾因散落硬编码出过缺陷）。
  - **脚本**：`scripts/harmony.sh` 新增 `h8selftest` / `h8selftest-red` / `h8shots` 三个动作
    （未改任何已有动作）。

- **验证**（模拟器 `127.0.0.1:5555`，nova 16 Pro / HarmonyOS 6.0.2 API22 / arm）：
  - `bash scripts/harmony.sh h8selftest 130` → `SEKB_HARMONY_SELFTEST PASS=26 FAIL=3 SKIP=3`；
    FAIL 三项全在**共享层 RAG 的 RDB 落地**（`rag_ingest`/`rag_retrieve`/`rag_delete`）：
    写进去的 `chunks.source_id` 读回来是空串（检索命中 `=@0.696` 来源名空、`deleteBySource` 删 0 行）
    → 根因在 `RdbStore.execute`/`RdbVectorStore`（工作流 F），已连同证据交给主线；**未算作 UI 已完成**。
    SKIP 三项是 `cloud_enroll/cloud_login/cloud_chat`（无账号无云端，**环境限制**且理由写清"不是已连上"）。
  - **反向验证**：`bash scripts/harmony.sh h8selftest-red 150` → 注入 `ping()==43` 的错期望后
    `selftest_red_check` **确实变红**（`PASS=25 FAIL=4`），脚本判定"必须恰好 1 个 FAIL"。
  - 自检表**当场抓到两个"判据写错"的缺陷**（`echoLen` 口径是 `text.length` 不是 UTF-8 字节；
    `CONTRACT PASS 128/128` 的 128 是通过数不是失败数）——已修并写进 README。
  - **看图复核**（`read_image`，四页各一张 + 徽章一张，见 `apps/harmony/docs/screenshots/`）：
    空状态**没有**把输入栏挤出屏幕；徽章与原因渲染正常；深/浅色未串。
    图还暴露一处**布局缺陷**：输入栏原先在 `ChatPage` 内（内层 `layoutWeight` + 固定高度两层嵌套），
    在整屏窗口 + 悬浮手势条下底部两行被裁掉 → 把输入栏与标签栏提到外层根 Column 后修复。
  - 附带两条**工具事实**：模拟器上 `uitest uiInput click` 的坐标与页面坐标对不上（点标签栏落到滑杆上，
    把阈值 0.40 改成了 0.50，被截图记录）→ 截图改用 `aa start -A SEKB_PAGE_*` 确定性开页；
    且 `aa start` 的 `-A` 必须写在 `-a/-b/-m` **之后**，否则 `onCreate` 收到空 action。
  - 未验：RDB 建库的间歇性 `14800037`（已排除目录不存在、库名过长、预建库文件三条路）；
    端侧失败自动改道云端 / `StreamGuard` / 路由事件上报（鸿蒙侧结构性无法同步驱动，见 README）；
    release 体积；PDF 导入。详见 `apps/harmony/README.md` 的 H8「未验 / 未成」一节。
