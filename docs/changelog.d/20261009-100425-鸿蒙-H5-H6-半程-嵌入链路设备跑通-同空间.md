## 2026-10-09（鸿蒙 H5/H6 半程：嵌入链路在设备上跑通，但同空间未达成——根因锁定到 `.ms` 转换忽略掩码输入）

- **背景**：按《鸿蒙端方案》§7.2 做 H5/H6 的嵌入端口：把 `kotlin-pending` 那份**重写**为
  当前模型口径（additive mask 由宿主喂入），并在设备上验"与 Android 同空间"（余弦 0.244）。

- **改动**：
  - 新增 `knspike/.../MindSporeBgeEmbedding.kt`（**重写而非搬运**：输入按**名字**选、
    掩码 = 可见 0 / 被掩 `-inf`（只掩 key）、CLS pooling + L2、**失败返回同数量零向量**）；
  - 新增 `EmbedSanity.kt` + NAPI `embedSanity` + `bash scripts/harmony.sh embed`（余弦/L2/确定性/
    降级契约/token 诊断/掩码写入读回/掩码取值扫描）；
  - `vocab.txt` 进包（源 = 宿主模型目录，与 Android 同一份）；`MsSessionCache` 进程内单例会话；
  - `predictTyped` 不再静默跳过未匹配输入；`MsSession.writeInputF32/readInputF32` 诊断；
  - 新增 host 侧实验脚本 `scripts/check_maskfree_padding_gap.py`（无需设备）。

- **验证**（模拟器 127.0.0.1:5555，`bash scripts/harmony.sh embed 90`）：
  - ✅ 已成立：模型加载 + 真实输入名与元素数（`input_ids=512`/`token_type_ids=512`/
    `sekb_additive_mask_zero=262144`）；分词与 host `tokenizers` **逐 id 相同**；
    512 维、`‖v‖=1.0000`、两次嵌入逐位相同；**失败返回同数量零向量**（HR8 第 4 条）；
    掩码写入读回**逐位一致**（256512 个 `-inf`）。
  - ❌ **未达成**：`cos=0.8154`，Android 基线 **0.244**（`EMBED FAIL 7/9`）。
  - **根因（两条实验定死）**：① host 侧用同一张 ONNX + 同一套 id + 同一个 `-inf` 约定算出
    **0.2439**（两图逐元素差 1e-7）→ 模型变体本身正确；② 设备侧把被掩位分别填
    `-1e9 / -65504 / -1e4 / -inf` → **四个值给出完全相同的 0.8154**。
    ⇒ 转换出的 `bge-maskinput.ms` **运行时完全忽略** `sekb_additive_mask_zero`（转换器把该图输入
    常量折叠了）→ padding 全部参与注意力 → 余弦被抬高。**这是模型转换链的缺陷，不是端口缺陷。**
  - 因此端侧嵌入**当前不能用于检索阈值标定**（空间与云端不一致，违反 RFC M3 不变量）。

- **顺带修掉的真缺陷**：`predictTyped` 静默跳过未匹配输入（改为两边齐全才跑）；
  输入角色按声明顺序取（`input_ids`/`token_type_ids` 元素数相同无法区分 → 改按名字）；
  反复 build/destroy 崩溃（两条栈：`MallocSubgraphInputs` / `LiteModel::Free` → 改单例会话）；
  界面渲染多段长报告导致 ArkUI `CustomNode::Render` SIGSEGV（界面只显示首行）；
  `@Synchronized` 是 JVM 专有（Kotlin/Native 编译错误）。
  并更正一处**我自己的假绿**：余弦判据原写 `cos < 0.95`（0.8154 也 PASS），已改为 `|cos-0.244|<=0.02`。

- **未验**：真正等到同一空间的嵌入（需修 `.ms` 转换链或换运行时）；H4/H5 的其余部分（HUKS 往返、
  RDB 向量库、检索评测同表）未开始。`scripts/model_to_ms_maskfree.py` 头部"带 padding 预期不一致"
