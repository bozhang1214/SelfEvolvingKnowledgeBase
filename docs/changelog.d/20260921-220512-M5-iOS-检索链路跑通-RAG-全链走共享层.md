## 2026-09-21（M5：iOS 检索链路跑通（RAG 全链走共享层）+ 端口③嵌入的调研结论）

- **背景**：端口③（端侧真嵌入）需要 ONNX Runtime iOS 或 Core ML；本轮先查清可行性，同时把
  **不依赖真模型的那一半**（整条检索链路）在 iOS 上打通——这条链路的代码全在共享层，
  打通它才谈得上"四端功能对等"。

- **改动**：iOS 自检新增 4 项 RAG 检查（chunking → 嵌入 → 向量库 → 检索 → 阈值 → 隐私闸门），
  嵌入用共享层的确定性桩（与 Android 在"ONNX 模型缺失"时的回退**同一条代码路径**）。
  顺带记录三条 Swift↔Kotlin 互操作事实：**Kotlin 默认参数不导出到 Swift**
  （`DeterministicEmbedding()`/`HostOllamaEmbedding(...)`/`Retriever(...)` 的默认值必须显式传，
  否则报 `'init()' is unavailable` 或 `missing arguments`）。

- **验证（模拟器实测）**：`SEKB_IOS_SELFTEST PASS=20 FAIL=0 SKIP=1`
  - ✅ `rag_ingest — 切片=1 嵌入=1 空间=stub-hash@256`
  - ✅ `rag_retrieve — 命中=1 首条分=0.244`
  - ✅ `rag_threshold_refuses — below_threshold:最高分=0.180<0.99`（"宁可说没有"）
  - ✅ `rag_device_only_gate — device_only_requires_on_device_embedding:当前嵌入=bge-m3@1024 非本机计算`

- **端口③ 调研结论（未完成，原因具体）**：
  ① 宿主 Ollama **没有嵌入模型**（`/api/tags` 只有对话模型），且国际链路此前不可用；
  ② **CocoaPods 未安装**，ORT iOS 静态库未验证；
  ③ Core ML 转换成本最高且要重标阈值（空间变了）。
  **下一步建议按序**：装 CocoaPods → `onnxruntime-objc` → 复用现有 int8 ONNX 模型（23.9MB）跑真嵌入；
  不行再退宿主嵌入；最后才考虑 Core ML。已写进 `apps/ios/README.md`。
