## 2026-09-23（职位采集：BOSS/智联 浏览器插件（路线 C）+ 导入支持结构化 JSON）

- **背景**：BOSS 采集一直卡在搜索接口 `sign` 签名（`code:37`），无头浏览器又被 `verify-sdk`
  清成 `about:blank`。继续逆向签名的收益/风险比很差（BOSS 一升级 JS 就失效）。
  改为**读用户自己浏览器里已渲染的页面**：不碰签名、不新增任何网络请求，
  在风控视角下与「人打开页面看了一眼」等价。

- **改动**：
  - 新增 `scripts/sekb-job-collector.user.js`（油猴脚本）：BOSS / 智联两站适配器，
    右下角面板「采集当前页 → 导出 JSON / 复制 JSON」，只读 DOM（无 fetch/XHR/轮询），
    采集结果存 `localStorage` 跨页累积、按 URL 去重。
  - `backend/app/services/job_service.py`：`parse_job_files` 新增 **结构化 JSON 导入**——
    `.json` 走 `_parse_json_jobs`（兼容 `{"jobs":[…]}` 与裸数组；字段名宽容处理
    `title`/`position`、`job_url`/`url`、`jd_text`/`jd`），保留公司/薪资/城市/链接；
    无标题条目跳过；坏 JSON 退回文本解析（不再把结构化字段压成一个「文件名=标题」条目）。
  - `docs/ops/10-JOB-SOURCES.md`：补「路线 C」整节（用法、选择器表、安全对比、已知边界）
    + **脉脉/智联渠道调研结论**——脉脉 web 端只有 B 端企业服务与社区，求职者无免登录
    职位列表页，**不接入**；智联无免登录 JSON（接口稳定返回空 `results`），浏览器渠道可用。

- **验证**：
  - `node --check scripts/sekb-job-collector.user.js` 语法通过；
  - `tests/unit/test_job_service.py` 新增 5 条 JSON 导入用例（结构化字段保留 / 裸数组+别名字段 /
    无标题跳过 / 坏 JSON 回退 / JSON 与文本混合），与既有用例共 **8 passed**；
  - 连带 `test_job_cache.py` 一起跑 **31 passed**。
  - **未验**：油猴脚本在真实 BOSS/智联页面上的选择器命中（需人工在浏览器里跑一次；
    选择器取自开源项目实测文档，站点改版可能需微调）。
