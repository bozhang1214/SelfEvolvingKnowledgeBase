## 2026-09-21（M5 端口①：iOS 网络传输（NSURLSession）实测通过——自检 10/10）

- **背景**：M5 的四个端口中，传输是最先要补的（没有它，iOS 端连不上任何端点）。
  共享层的 `HttpTransport` 是同步接口 + 逐行回调，Swift 侧要同时解决"同步语义"与"真流式"两件事。

- **改动**：
  - `apps/ios/App/UrlSessionTransport.swift`：`URLSession` 实现 `HttpTransport`——
    `postJson`/`get` 用完成回调 + `DispatchSemaphore` 变同步；`postJsonStream` 用
    `URLSessionDataDelegate` **按 `\n` 切行**回调（不缓冲整个响应体）。
  - 自检新增两项：真实 GET 宿主 Ollama（`/api/tags`）与流式 POST（`/api/generate`，逐行计数）。
  - `scripts/ios_app.sh`：编译全部 Swift 源文件；launch 前 `terminate`；抓日志前等 45s。

- **验证（模拟器实测）**：
  ```
  SEKB_IOS_SELFTEST PASS=10 FAIL=0
  [PASS] transport_get_host_ollama — code=200 bytes=3474
  [PASS] transport_stream_lines — code=200 行数=9（num_predict=8，验的是传输不是模型）
  ```

- **踩到的四个坑（写进 `apps/ios/README.md`）**：
  1. `simctl launch` 对**已在运行**的 App 只切前台，`onAppear` 不再触发 → 自检挪到 `App.init()`
     且 launch 前先 `terminate`；
  2. 但 `App.init()` 里**不能同步阻塞主线程**等网络 → 自检放后台队列（否则日志里只有 trustd
     的请求痕迹，永远等不到自检输出）；
  3. 抓日志前要等足（含冷加载）；
  4. 测流式**必须给生成加上限**（`num_predict`）：否则模型长篇生成、超时前流不结束，
     `statusCode` 拿不到（`code=-1` 而"行数"上万）；且 `URLSession` 的 delegate 与完成回调
     **跨队列**，状态码要在 `didReceive response` 里**加锁**记录。
