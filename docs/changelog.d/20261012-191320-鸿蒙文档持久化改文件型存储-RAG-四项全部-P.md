## 2026-10-26（鸿蒙文档持久化改**文件型存储** → RAG 全部 PASS，自检 FAIL 归零）

### 决断与结果
鸿蒙 RDB 的 **NDK C 路径**被证明读一致性不可靠（同一进程同一句柄相邻调用互相矛盾；
事务/游标长度/列名索引/多句柄/SQL 聚合/嵌入打分**都已逐一实验排除**）。
而**文件 I/O 在鸿蒙上是可靠的**（聊天历史就是"文件 + 先写 `.tmp` 再 rename"，跨重装能恢复）。
向量索引是**可重建的派生数据**，不需要数据库能力 ⇒ 主线改为 **`FileVectorStore`**，
`filesDir` 经 NAPI 传进 Kotlin（第 5 个参数；非空即走文件型，空则退回 RDB 作对照）。

**设备实测（连续两次一致）**：
```
[PASS] rag_store_open       — 自检库已打开
[PASS] rag_ingest           — 列表里 2 篇（总片段 2 段）｜登记 [__selftest__:1,__selftest_other__:1]
[PASS] rag_retrieve         — 首条=__selftest__@0.696；库里 2 行且 norm=1.0000
[PASS] rag_delete           — 删除 1 段；剩余 1 篇（删前 2）；**别的文档还在=1**（没清库）
[PASS] rag_selftest_cleanup — 残留 0 篇
SEKB_HARMONY_SELFTEST  PASS=24 FAIL=2 SKIP=8
```
两个 FAIL 全是**宿主环境项**（`edge_reachable`/`edge_models`：本机 Ollama 未起），
**不含任何端侧功能缺陷**——这是鸿蒙自检第一次做到"FAIL 里没有功能问题"。

### `FileVectorStore` 的设计（都在文件头注释里）
- 行式 + 十六进制格式（`D…` 文档 / `C…` 切片 / `S…` 空间戳），**故意选最笨但最不易解析错的**；
- 写入**先 `.tmp` 再 `rename`**（与 `HistoryStore` 同一条经验）：崩溃不留半个库；
- 每次变更**整库重写**（数据量小，换来实现简单与"读回来的一定是刚才那份内存状态"）；
- **空间戳校验**与 RDB 实现同口径：换模型**当场报错**，绝不混算余弦；
- 两个接口（`VectorStore`/`DocumentRegistry`）**一字未改** ⇒ 共享层
  `KnowledgeIndex`/`Chunking`/`Retriever`/评测集**零改动**（端口模式的价值就在这里）。

### 顺带修的两处
1. **探针关闭时记 SKIP 而不是 FAIL**：FAIL 的语义是"测得不对"，"没测"必须记 SKIP——
   此前那条关掉的探针一直占着一个 FAIL，看起来像还有缺陷（本轮汇总因此从 FAIL=3 降到 FAIL=2）。
2. **两个 Kotlin/Native 踩坑**（写进注释免得重踩）：
   - `cp[i]` 指针下标在这个文件里会被解析到 `MatchGroupCollection.get(name)`（正则那个扩展！），
     报出 `actual type is 'MatchGroup?'`。**碰原生缓冲优先用「Kotlin 数组 + `usePinned` + `addressOf`」**。
   - `java.io.File`/`Character.digit` 在 Kotlin/Native 里**不存在**（前者正好是 `check_edge_facts`
     的"JVM 专有 API"扫描项）；用 `platform.posix.mkdir` 与手写十六进制转换替代。

### NDK C 路径的去留
`RdbVectorStore.kt` + `RdbIdProbe.kt` + 全部探针**保留在仓库**：它们已经证明了很多"**不是**什么原因"
（这是排查里最贵的信息），将来平台修好 RDB 或要做对照实验时可直接切回（`filesDir` 传空串即回 RDB）。
