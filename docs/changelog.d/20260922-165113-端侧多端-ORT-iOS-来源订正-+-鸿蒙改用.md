## 2026-09-22（端侧多端：ORT iOS 来源订正 + 鸿蒙改用 MindSpore Lite）

- **背景**：M5 端口③（iOS 端侧嵌入）与 M6 spike 第 3 条（鸿蒙端侧嵌入）此前被记为"网络阻塞"——
  实测 `github.com` 不可达（HTTP 000）。owner 反馈"本机可以访问 github"，遂逐项复核，
  结果发现**两条阻塞的真正原因都不是 GitHub 不可达，而是我们找错了产物来源**。

- **改动**：
  - **iOS 侧（订正）**：ORT 的 iOS 产物**不在 GitHub**，而在 `download.onnxruntime.ai`。
    获取路径：CocoaPods 规格库（`cdn.cocoapods.org` → 301 跳 `cdn.jsdelivr.net/cocoa`）
    的 `onnxruntime-c/1.20.0` podspec 里 `source.http = https://download.onnxruntime.ai/pod-archive-onnxruntime-c-1.20.0.zip`。
    该 URL 实测 **HTTP 200 / 44,218,716 B**，`curl -L` 直下，**不需要 GitHub、也不需要装 CocoaPods**。
    产物三切片齐全（`ios-arm64` 真机 / `ios-arm64_x86_64-simulator` 模拟器 / `macos-arm64_x86_64`，
    **后者顺带解锁 M8 Mac 端**），`nm` 确认导出 `_OrtGetApiBase`、`ORT_API_VERSION 20` 匹配。
  - **鸿蒙侧（方案微调）**：鸿蒙端侧嵌入**不需要 ONNX Runtime**。Kotlin/Native 的 OHOS 工具链
    已预置 HarmonyOS **MindSpore Lite** 平台绑定：`platformDef/ohos_{arm64,x64}/MindSpore.def`
    （`package = platform.MindSporeLiteKit.MindSpore`、`linkerOpts = -lmindspore_lite_ndk`）、
    预编译 cinterop klib、以及 sysroot 内 `include/mindspore/*.h` 与三个 ABI 的链接桩。
    桩的 `OH_AI_*` 符号由 `llvm-nm -D` 确认，真实现由鸿蒙系统镜像在运行期提供。
    → spike 第 3 条验收口径由"ONNX Runtime 自建跑通嵌入"改为"在鸿蒙上跑通端侧嵌入（运行时用系统 MindSpore Lite）"，
    **不改动共享层契约**（`apps/shared/embed/` 只约定"文本 → 定长归一化向量"，换运行时按 RFC 既有做法重标阈值）。
  - **文档**：`apps/ios/README.md`、`apps/harmony/README.md` 同步订正，并把"ORT 自建"整段标注为已作废的过程记录。

- **验证**：
  - ORT iOS 归档 sha256 `50891a8aadd17d4811acb05ed151ba6c394129bb3ab14e843b0fc83a48d450ff`，
    与 `content-length` 一致；`lipo -info` / `file` 逐切片确认架构。
  - MindSpore Lite 三条证据均在 `.tooling/konan/` 下逐项 `ls` / 读 `MindSpore.def` / `llvm-nm -D` 确认。
  - `bash docs/tech/.validation/doc_guard.sh` → **6/6 全通过**（HEAD=3eced3e）。
  - **未完成（如实记录）**：xcframework 尚未链进 iOS App、真嵌入与阈值重标未做；
