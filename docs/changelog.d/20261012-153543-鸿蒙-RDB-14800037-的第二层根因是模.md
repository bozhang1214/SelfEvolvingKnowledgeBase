## 2026-10-26（鸿蒙 RDB `14800037` 的第二层根因：**模拟器实例的 storage 未就绪**；另修 `dbName` 空串）

上一轮把 `14800037 = RDB_E_CREATE_FOLDER_FAIL` 归到"`databaseDir` 的父目录不存在"。
本轮在**新起的模拟器实例**上发现还有第二层根因，两件事都必须记下来，否则下一个人会以为修好了。

### ① 第二层根因：**实例 storage 未就绪**，重启实例即恢复（可复现）

同一份代码、同一个目录状态，表现却相反，差别只在**模拟器实例的生命周期**：

| 场景 | `RDB 目录自检` | `rag_store_open` |
|---|---|---|
| 新实例首次启动后（应用进程从未成功建过 storage） | `父目录存在=true 之前存在=true 之后存在=true mkdir=ok` | ❌ 仍报 `14800037`（连跑两次都一样） |
| **把该实例停止再启动**（`Emulator -stop` → `-hvd … -path …`）后 | 同上（完全一致） | ✅ **PASS** |

即：**目录存在且可写，并不足以让 RDB 建库**；这台实例需要一个"重启一轮"才会把应用的
`el2` 存储区真正备好。诊断上很坑：三条诊断（父目录/之前/之后）全绿却依然失败，
所以**不能**只看这三条就宣布"环境没问题"。

复现命令（可重放）：
```bash
EMU=/Applications/DevEco-Studio.app/Contents/tools/emulator/Emulator
"$EMU" -stop "nova 16 Pro" ; sleep 12
nohup "$EMU" -hvd "nova 16 Pro" -path "$HOME/.Huawei/Emulator/deployed" &
# 等 hdc list targets 出现 127.0.0.1:5555，再跑自检：
bash scripts/harmony.sh h8selftest 120
```
> 顺带一条**工具教训**：`Emulator -hvd/-path/-imageRoot` 是**可用**的（文档早前记过 `-path` 要指
> **父目录** `…/deployed`），所以**鸿蒙模拟器现在可以完全由命令行起停**，不必依赖 DevEco 界面。
> 这条写进来，是因为本轮模拟器中途挂掉后正是靠它恢复的（否则所有设备侧验证都会停摆）。

### ② 真缺陷：`dbName` 空串 → 建出一个"没有名字的库"（写入 A、读取 B）

`SekbApp.open(mp, vocab, dir, dbName)` 直接把 ArkTS 传来的 `''` 当 `storeName` 用
（`openRag()` 传空串的约定是"用默认库"），而它同时把 `activeDb` 也设成 `''` →
**幂等判断失效 + 库名空**。修法：`val wantDb = dbName.ifBlank { DOC_DB }`，
`activeDb`/`RdbVectorStore`/`LocalDocSession.dbName` 全用 `wantDb`。
（ArkTS 侧保持传空串 = "默认库"，归一只有一处，避免两处默认值各说各话。）
