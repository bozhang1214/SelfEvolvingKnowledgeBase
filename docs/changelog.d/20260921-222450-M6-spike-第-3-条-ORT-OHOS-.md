## 2026-09-21（M6 spike 第 3 条：ONNX Runtime 的 OHOS aarch64 编译启动）

- **背景**：镜像可达后，把"实际编译"这一步真正推起来。

- **纠正了三处"文档没写、只有撞了才知道"的细节**：
  1. `--ohos_arch` 的合法值是 **`aarch64`**（不是 `arm64`）——报错信息里给出可选列表
     `riscv64/aarch64/armv7/x86_64`；
  2. 移植版**只带 riscv64 的工具链文件**，arm64 要自己写 → 已新增
     `cmake/ohos_aarch64.toolchain.cmake`（按 `cmake/ohos_<arch>.toolchain.cmake` 的查找规则命名）；
  3. 主机环境两处缺口：系统 python3 是 **3.9**（ORT 脚本用 `match`，需 3.10+）→ 用后端 venv 的
     **python 3.11**；主机**没有 cmake/ninja** → 用 Android SDK 自带的那份（`cmake/4.1.2/bin`，含 ninja）。

- **状态**：编译已在后台启动（`--ohos --ohos_arch aarch64 --skip_tests
  --cmake_extra_defines onnxruntime_BUILD_SHARED_LIB=ON`，`build_dir=build/ohos_aarch64`）。
  ONNX Runtime 体积大、编译耗时长，**结果下一轮取**；成功后把 `libonnxruntime.so` 用于
  spike 第 3 条后半段（跑通 bge-small-zh 出向量）。
