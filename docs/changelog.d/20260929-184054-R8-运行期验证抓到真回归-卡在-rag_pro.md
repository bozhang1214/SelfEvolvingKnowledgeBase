## 2026-09-25（R8 运行期验证：**抓到一个真回归**——卡在 `rag_provider`，ORT 反射被剥）

- **为什么值得做**：§1.12 只验了 R8 的**体积**，运行期一直记为缺口，理由正是"R8 可能删坏代码"。
  本轮手机短暂解锁，把缺口补上——**立刻抓到一个真问题**。

- **已验证**：release 包（带签名、20.8 MB、无 `DEBUGGABLE`）安装成功、真机自检
  **前 10 项 0 FAIL**，然后**卡在第 11 项 `rag_provider`**（ONNX 嵌入提供者创建）：
  此后无任何自检输出，**无异常、无崩溃、进程存活**。

- **诊断**：`ai.onnxruntime.**` 的 Java API 通过 **JNI + 反射**加载类与 native 库，
  R8 看不到这些反射引用 → 剥掉/改名 → provider 创建不出来。
  **这正是"R8 必须跑一轮 E2E"的价值：体积数字好看不代表还能跑。**

- **已应用的修法（待重验）**：`proguard-rules.pro` 增加
  `-keep class ai.onnxruntime.** { *; }` + `-keepclassmembers` + `-dontwarn ai.onnxruntime.**`；
  重建 `BUILD SUCCESSFUL`。

- ⚠️ **重验未完成**：补齐 keep 规则后重装失败、且手机随后从 adb 断开 → **"第 11 项是否恢复"尚未验证**。

- **顺带查清两条 release 包操作约束（都很容易误判）**：
  1. **release 构建必须带 `SEKB_EDGE_URL`**：我漏带时包内是默认 `10.0.2.2`（模拟器地址），
     真机上所有 `edge_*` 全 FAIL——**表现极像"R8 把网络搞坏了"**，实为构建参数漏了。
  2. **非 debuggable 包不能用 `run-as`** → `push-policy` 报 `run-as: package not debuggable`，
     故 3 个策略项在 release 自检里**只能 SKIP**，release 满分约 28（+SKIP）而非 32。
     记住这个口径，否则会把"推不进策略包"误当成缺陷。
