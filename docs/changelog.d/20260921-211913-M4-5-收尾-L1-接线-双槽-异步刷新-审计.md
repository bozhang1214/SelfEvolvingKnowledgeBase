## 2026-09-21（M4.5 收尾：L1 接线——双槽/异步刷新/审计/阈值进检索/自检项 + adb reverse 修法）

- **背景**：上一步把"策略校验与应用"这个**纯函数**做完了（`EdgePolicy`），这一步把它接进产品路径：
  存哪、什么时候拉、失败怎么办、阈值怎么进检索、怎么在自检里看见。

- **改动**：
  - `device/SharedPrefsPolicyStore.kt`（Android 实现）：与设备凭证同一个 `sekb_device` prefs；
    双槽（active/previous），`save` 时先把旧 active 挪进 previous（顺序不能反，否则中途失败两份都丢）。
  - `AppContainer`：新增 `policyStore` / `policyFetcher` / `lastPolicyResult` / `policyAudit`（最多留 50 条），
    `refreshPolicy()`（拉→验签→应用→落盘；**失败不改状态**只写审计）、`rollbackPolicy()`、`policyVersion()`、
    `startPolicyRefreshLoop()`（启动异步拉一次 + 每 6h，守护线程，异常只记日志）。
  - `SekbApp.onCreate` → `startPolicyRefreshLoop()`：**不阻塞启动**（拉不到照样能聊天）。
  - `container.retriever` 的 `minScore` 改为取落盘策略里的 `retrievalMinScore`（没有则本地默认 0.5）。
  - 自检新增两项：`policy_refresh`（无设备凭证 → SKIP）、`policy_rollback_guard`（无上一份必须干净跳过）。
  - 构建期新增 `-PsekbEdgeUrl=` 覆盖端侧端点地址；`scripts/emulator.sh` 起好模拟器后自动
    `adb reverse tcp:11434 tcp:11434`。

- **验证**：
  - `bash scripts/android.sh test` → **231 tests, 0 failed**（新增 `PolicyFetcherTest` 10 条：
    HTTP 错误/网络异常/签名不符/灰度跳过都**保持原配置**、第二次保存进 previous 槽、回滚恢复、
    审计里不出现策略正文、设备 token 正确带上、端点路径正确）。
  - **E2E 本轮未跑通（如实记录）**：自检第 1 项 `edge_reachable=false`——宿主 Ollama 只绑
    `127.0.0.1:11434`，当前模拟器访问不到 `10.0.2.2:11434`。修法已落进脚本（`adb reverse` +
    `-PsekbEdgeUrl=http://127.0.0.1:11434/v1`），下一轮 E2E 应能跑满 29 项。
  - `doc_guard` 6/6（活数字 `android_unit_cases=231`）。

- **遗留**：`retrievalMinScore` 生效时机（改策略后需重建 `Retriever`——目前只在启动时读一次）；
  `promptPacks` 接入真实 LLM 调用点（单独一轮）。这两条已写进工程议题文档的"仍待做"。
