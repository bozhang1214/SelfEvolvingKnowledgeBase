## 2026-09-24（Android 真机自检 FAIL 归零：28 PASS / 0 FAIL / 4 SKIP）

- **背景**：上一轮真机首跑是 `PASS=20 FAIL=1 SKIP=7`。那 1 个 `FAIL` 经查是**自检逻辑缺陷**
  （`privacy_device_only_local_gate` 把 `calls == 0` 当成两分支共同前置条件，导致本机端点下
  正确行为被判失败），已修但未复跑。本轮 owner 允许了手机侧"通过 USB 安装应用"，重装复跑完成闭环。

- **结果**：真机（华为 Mate 40 Pro / HarmonyOS 4.2 = Android 12 基座）自检
  **`PASS=28 FAIL=0 SKIP=4`** ✅ —— **`FAIL` 归零**。

- **两个新证据值得单独记**：
  1. `privacy_device_only_local_gate` 转 **PASS**，实测值 `本机=true 端侧调用=1 原因=escalation_blocked:device_only`
     —— 即 **R10「本机允许执行 DEVICE_ONLY，但仍不许升级」那一半第一次被真正跑到并通过**
     （此前在模拟器上因端点非本机，这一半从未被覆盖）。
  2. `policy_refresh — 未应用：policy_bad_signature` 是 **PASS**：L1 策略的验签**正确拒绝了坏签名**。
  3. 样本 push 后新增 6 项全部 PASS，其中 `rag_pdf_extract` 抽到 **78 字符 / 1 页**，
     与 iOS/macOS 同一份样本的 78 字符**完全一致**（三端交叉印证）；
     `rag_delete_file` / `rag_pdf_delete` 证明**删单篇不误清全库**（文档数 4→3、剩余切片=3）。

- **剩余 4 个 SKIP 全是缺前置条件**（`cloud_login` 缺账号；`policy_apply_rebuild` /
  `policy_rollback_restores_threshold` / `policy_threshold_wired` 缺注入的策略包），
  与模拟器基线同性质，**不是功能缺口**。

- **改动**：`apps/android/docs/VERIFICATION.md` §1.1 更新为最终结果并补上 PDF/删除两项证据；
  `docs/COORDINATION.md` 按约定删除本轮认领行。
