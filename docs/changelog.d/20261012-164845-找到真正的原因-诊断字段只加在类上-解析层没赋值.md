## 2026-10-26（找到"诊断字段读不到"的真正原因：**只加在类上、解析层没赋值**；并拿到 RDB 读路径的矛盾证据）

### ① 真原因：我自己漏了赋值（**是我加的断言抓出来的**）
`SekbNative.ets` 的 `RagOpResult` 类上加了 `dbChunks/allRows/sizeErr/allErr/rawJson`，
**但 `ragIngest()` 的解析块里一个都没赋值**（只解析了 `ok/chunks/zeroFilled/millis/note`）。
于是它们恒为类默认值 `-1`/`''`，报告里看起来就是"Kotlin 侧诊断没执行"。

**我为此连着两轮怀疑错方向**：先怀疑"打包陈旧/不同源"（上一轮已用哈希证伪），
再花一轮做"版本标记"的思路。真正抓住它的是我上一轮自己加的那条断言
`rag_diag_fields_present`——**断言写对了，问题在解析层**。已修（四个字段各自赋值）。
教训：**给返回值加字段时，类、解析、断言三处要一起改**；而"加一条会红的断言"比"多打几行日志"有效得多。

### ② 修好之后，拿到的东西比预想的重要得多

```
rag_ingest_bridge  PASS  dbChunks=0 allRows=0 ｜ 原始报文=
   {"ok":true,"chunks":1,"zeroFilled":0,"millis":0,"note":"已导入…1 段，嵌入耗时 0ms",
    "space":"BAAI/bge-small-zh-v1.5@512","dbChunks":0,"allRows":0}
```
**`ingest` 自报 `chunks=1`，而同一次调用里**立刻**回读 `size()/all()` 都是 `0`** ——
写入与回读在**同一次调用内**就不一致。这是"写入没落地"的直接证据（且不是异常：`sizeErr/allErr` 为空）。

### ③ 五层探针（`rag_source_id_roundtrip` / `harmony.sh rdbid`）给出的**互相矛盾**的明细
```
FAIL write_size          — size=1（期望 1）        ← 值对、但断言形态与文案不一致（我写的判据本身有瑕疵）
FAIL read_single_column  — source_id='__selftest__'（期望 doc-probe）
FAIL read_multi_column   — id='<null>' source_id='__selftest__'（期望 doc-probe#0 / doc-probe）
PASS read_all_path       — 条数=1 首条 id='doc-probe#0' source='doc-probe' dim=0
FAIL delete_by_source    — removed=0（期望 1）
PASS size_after_delete   — size=0（期望 0）
```
读法（这三条放在一起只有一种自洽解释）：
**同一个探针库里同时存在两个"世界"** ——
① `all()`（生产读法，四列 + BLOB）读到了**刚写的** `doc-probe`，但 `dim=0`（BLOB 解出来是空向量）；
② 单列/多列 `SELECT`（同一个 `chunks` 表！）读到的却是**上一轮遗留的 `__selftest__`**；
③ `id` 列在 ② 里甚至是 `<null>`。
即：**`chunks` 表的读写不是同一份数据**，而且 `size()=0` 与 `all()=1 条` 互相矛盾
（同一个句柄、同一张表、相邻两次调用）。
→ 结论：问题不在"输入/掩码/阈值"，而在 **RDB 绑定层的事务/游标/可见性**（`RdbStore`/`RdbVectorStore`
读路径），这也解释了此前所有"写进去了却读不到/读到旧数据"的现象。

### ④ 下一轮的最短路径（两条都写清楚，别再来回试）
1. **先验事务**：`upsertChunk` 里 `beginTransaction()/commit()` 的**返回值从未被检查**。
   怀疑点：`commit()` 未生效（或 `OH_Rdb_Execute` 在事务中的可见性语义与预期不同）→
   数据只存在于当前事务里，`size()` 看到 0、换读法又看到旧行。
   做法：把三个事务函数的返回值全部断言出来（`rc != 0` 就报错），并把 `size()` 放在
   `commit()` 前后各测一次 —— 一次运行就能判定。
2. **若事务没问题**：改用 **ArkTS `relationalStore`** 实现这两个端口（RFC 里 C3 的原意），
   NDK C 路径作为备选。代价是"端口实现从 Kotlin 挪到 ArkTS"，但 `VectorStore`/`DocumentRegistry`
   接口不变（这本来就是端口的意义）。**不再往 NDK C 路径里加时间**。
