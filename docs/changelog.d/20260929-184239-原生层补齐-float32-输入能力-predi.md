## 2026-09-25（原生层补齐 float32 输入能力：`predictTyped`——M6 第 4 条的前置缺口）

- **补的是能力缺口，不是修 bug**：模型侧打通后（转换/等价/运行三项齐备、掩码由宿主喂入）
  去看原生层能否驱动它——**不能**。`MsLite.kt` 原本只有 `predict(Map<String, LongArray>)`，
  **只能喂 int64**；而 `sekb_additive_mask_zero` 是 **float32**。
  即**即使 `.ms` 已能跑，原生层也喂不进那个输入**。

- **改动（纯新增，不动既有已验证代码）**：
  - 新增 `Feed`（`I64`/`F32`）与 `predictTyped(feeds: Map<String, Feed>)`；
  - 既有 `predict(Map<String, LongArray>)` **一行未改**（已过验证，不冒回归风险）；
  - `predictTyped` 逐个输入**显式校验元素数与声明类型**。
    原因：`OH_AI_TensorSetData` 返回 void、**无状态可查**，类型/长度错配**不报错**、
    只表现为"向量不对"——最难查的一类问题。

- **验证（按仓库口径，只到 build+link）**：
  `kn` → `libkn.so` arm64-v8a 2.5M / x86_64 2.0M；
  `hap` → HAP 96M，且两个 ABI 的 `libknspike.so` 各引用 4 个 KMP 入口、模型 rawfile 在包内。

- ⚠️ **口径**：以上只证明"产物齐备且 NAPI↔KMP 引用成立"；**"能装能起 + 真的调通"
  属 spike 第 4 条**，需签名 HAP + 设备/模拟器，**仍未做**。

- **M6 第 4 条还差**：① 包内模型换成可运行的 `bge-maskinput.ms`（当前是会挂起的静态版）；
  ② 调用方计算 additive mask（可见 0 / 被掩 -inf，`[1,1,512,512]`）并用 `predictTyped` 传入；
  ③ 在模拟器/设备上验证（需 DevEco 模拟器镜像）。
