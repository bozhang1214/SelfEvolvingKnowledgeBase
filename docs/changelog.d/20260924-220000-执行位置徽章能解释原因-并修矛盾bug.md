## 2026-09-24（执行位置徽章"能自己解释原因"，并修掉一个自相矛盾的 bug）

- **背景**：owner 问「提示"已上云（端侧不达标）"是什么意思」。查清后发现**UI 里没有任何地方**回答
  "为什么"——上一轮我把调试用的"最近决策"一行删掉了，却没把原因搬到别处（**我造成的缺陷**）。
  而这个徽章是端侧产品的核心承诺（设备专属数据不出端）的可视化，"为什么出端"必须用户自己能看懂。

- **改动**：
  - `Bubble` 分两个字段存原因：`reason`（路由阶段）+ `escalateReason`（升级阶段），**挂在气泡上**
    而不是全局字段——用户问的是"**这一条**为什么上云"，全局字段往上翻就没了依据。
  - 新增 `ui/PlaneExplain.kt`：原因码 → 用户能懂的一句话（路由/隐私边界/升级信号三类），
    徽章可点开展示。**设计原则：认不出的码原样透出**（`原因：<code>`），绝不返回"未知原因"——
    这条原则当场见效：真机上暴露了我没见过的 `edge_unavailable`，随后补进翻译表。
  - 覆盖 `edge_preferred`、`input/output_over_edge_budget(N>M)`（保留真实数字）、
    `device_only_data`、`escalation_blocked:device_only[_requires_local_runtime]`、
    以及 7 个升级信号（`degenerate`/`timeout`/`low_confidence`/`json_invalid`/`empty`/
    `tool_hallucination`/`context_overflow`）。

- **⚠️ 过程中修掉一个自己引入的严重 bug**：第一版从 `decision.plane`（**计划**走的平面）推结论，
  而徽章依据 `execution.primaryPlane`（**实际**完成的平面）——而"升级"的定义恰恰是"计划本机、实际云端"，
  两者必然不一致：徽章说"已上云"，解释却说"这次在本机完成"。
  **自相矛盾的解释比没有解释更糟**（会让用户不再相信任何徽章）。已改为由调用方传入与徽章**同源**的事实。
  顺带修掉"吞掉后半段"的解析缺陷：`describe()` 原本只按逗号切分，`edge_preferred · degenerate`
  会被前缀正则命中第一段而**整段吞掉升级原因**。

- **验证**：
  - `bash scripts/android.sh test` → **256 用例 / 0 失败**（`PlaneExplainTest` 10 条，含两条回归测试：
    "升级场景不许声称在本机完成"、"` · ` 组合码不被截断"）。
  - **真机实测**（Mate 40 Pro）：真实触发一次"已上云"，展开显示
    「端侧没能达标（原因：edge_unavailable），这次改由云端重答。」——与徽章一致。
  - 顺带在真机首次确认 Markdown **表格**渲染正确（此前只做过代码对齐）。
  - `doc_guard` 6/6；取舍与证据记入 `apps/android/docs/VERIFICATION.md` §1.3。
