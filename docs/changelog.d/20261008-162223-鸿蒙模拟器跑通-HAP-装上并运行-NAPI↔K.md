  2. **NAPI↔KMP 在真实 OHOS 运行时上跑通**（截图证据）：`sekb_spike_ping() = 42`、

- **仍未通过**：MindSpore 端侧嵌入返回 `-5`（`MsStep.BAD_DTYPE`）。本轮修掉**两个确实成立**的原因：
  1. 探测函数遗留的"**所有输入必须 int64**"判据——模型现有 float32 掩码输入，该判据在设计上即为假；
  2. **按名字找输入不可靠**：`.ms` 存的是 ONNX 原名（实测含 `sekb_additive_mask_zero`、无
     `attention_mask`），而运行时名字可能是转换器内部的 `Parameter_N`（转换期报过
     `Parameter_1 not found in graph`）→ 改为**按类型识别角色**（1 个 float32 = 掩码，2 个 int64 = ids/types）。
  **修完仍返回 -5**，故还有别的原因。

- **下一步（不猜，先取事实）**：把设备上**实际的输入名与类型**报告出来——

  或用 `hilog` 打印后 `hdc shell hilog | grep SEKB`。拿到真实名字/类型后 `-5` 可一次定位
  （很可能：转换器把掩码输入折叠/省略了，运行时只剩 int64 输入）。
