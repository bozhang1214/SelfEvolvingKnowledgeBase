## 2026-09-21（M5 第二步：iOS App 骨架跑通模拟器——SwiftUI + SharedCore，自检 8/8）

- **背景**：framework 能在 host 上跑通只证明"共享层可用"；M5 要的是**端侧宿主真的起来**。
  本步目标：SwiftUI 界面 + 复用共享逻辑 + 能在 iOS 模拟器上装、起、出结果。

- **改动**：
  - `apps/ios/App/SekbApp.swift`：SwiftUI 骨架（按钮触发端侧自检 + 结果列表）；
    自检项直接调用 `SharedCore` 的真实逻辑（摘要、规范化 JSON、路由决策、R10 两条对照、
    流式守卫零外泄、工具调用解析）。
  - `apps/ios/App/Info.plist`：手工 `.app` 包所需的最小 plist。
  - `scripts/ios_app.sh [boot|build|run]`：**不手写 `.xcodeproj`**——`swiftc` 直编 iOS 模拟器目标
    + 组装 `.app` + `simctl install/launch`，全脚本化可复现。

- **验证（模拟器实测输出）**：
  ```
  SEKB_IOS_SELFTEST PASS=8 FAIL=0
  [PASS] digests_hmac — f7bc83f430538424…            （Apple 侧 CommonCrypto 实测）
  [PASS] canonical_json — {"a":[1,2],"b":1}          （与 Python 逐字节一致）
  [PASS] router_decision — plane=edge reason=edge_preferred
  [PASS] r10_local_allows_but_never_escalates        （本机端点：可执行、不许升级）
  [PASS] r10_remote_edge_blocks                      （远端端点：一个请求都不发）
  [PASS] stream_guard_zero_leak — 阈值前放行=0 chars
  [PASS] toolcall_parse — device_time
  [PASS] retriever_default_threshold — 0.5
  ```

- **四个环境/语言坑（都记进 `apps/ios/README.md`）**：
  1. `simctl launch --console-pty` 在受限环境里**分配 pty 失败**（`Unable to open pty: Error 1`）
     → 改正常启动 + `simctl spawn <dev> log show --predicate 'process == "Sekb"'` 抓输出；
  2. `print` 不进模拟器统一日志 → 自检输出走 `report()`（`print` + `NSLog` 两路）；
  3. 单文件 `swiftc` 按脚本模式编译，`@main` 会报
     `'main' attribute cannot be used in a module that contains top-level code` → 加 `-parse-as-library`；
  4. Kotlin sealed interface 在 Swift 里是 `any StreamGuardDecision` + 具体子类
     （`StreamGuardDecisionRelease`），**不能**写 `case let StreamGuardDecision.Release(...)`。

- **顺带修正一条自己的错误断言**：第一版把 R10 写成单条"DEVICE_ONLY 必须被拦"，
  而 iOS 用的是 `127.0.0.1`（本机）→ 正确地不拦，我却当成 FAIL。
  现已改成**两条对照**（本机可执行但不许升级 / 远端直接拦），这才是 R10 的完整语义。

  然后让 iOS 自检项与 Android 等价（当前 8 项 vs Android 30 项）+ 检索评测数字一致。
