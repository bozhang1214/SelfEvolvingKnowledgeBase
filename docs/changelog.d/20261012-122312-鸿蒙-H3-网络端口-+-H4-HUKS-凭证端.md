## 2026-10-12（鸿蒙 H3 网络端口 + H4 HUKS 凭证端口 · 模拟器实测）

一条命令跑完两轮取证：`bash scripts/harmony.sh net 30`
→ `H3 PASS 3/3`（两轮）、`CRED PASS 8/8`（次轮 = force-stop 后不重装）、明细 FAIL=0。

### H3 网络端口（`@ohos.net.http`，C2 已于 2026-10-25 改判）

* **端口注入选「网络调用留在 ArkTS」（方案 ii），不是「NAPI 把 ArkTS 回调注册给 Kotlin」（方案 i）**。
  理由是一条**结构性死锁**，不是实现水平：共享层 `HttpTransport` 是同步接口，而 Kotlin 是被 ArkTS
  **同步**调进来的（NAPI 在 ArkTS 线程执行）——Kotlin 若在其中等 `await`，回调只能排进**同一条**
  被卡住的线程的队列。iOS 能用 `DispatchSemaphore` 是因为 URLSession 回调在另一条线程上。
  代价：`HttpTransport` 接口在鸿蒙侧暂时没有实现类（接口一行未改）；协议与解析仍只有一份。
* ArkTS 侧 `model/NativeHttpBridge.ets`：`request`（缓冲）+ `requestInStream` + `on('dataReceive')`
  按 `\n` 切行；**不解释 SSE**，每个完整行同步调 `h3StreamLine` 交给共享层 `SseParser`。
* 判据由 ArkTS 把**已观测事实**交给 Kotlin（`h3Probe`/`h3Stream`），Kotlin 负责判定与渲染——
  "判据只有一份"，且没有反向回调。
* 实测（宿主 Ollama 经 `hdc rport tcp:11434`）：
  `transport_get_host_ollama` code=200；`transport_stream_lines` ArkTS 4 行 / Kotlin 4 行；
  **两条反向验证**：`transport_refuses_bad_endpoint`（无监听端口 → code=-1）、
  `transport_refuses_404`（能连上但路径不存在 → 404）——证明判据不是摆设。

### H4 凭证端口（HUKS，纯 Kotlin/Native cinterop）

* `libhuks_ndk.z.so` 已由 HR9 探针证明在设备上可加载；HUKS **不在** OHOS Kotlin fork 的平台
  klib 里（与 RDB 不同），所以自建 `cinterop/huks.def` + `linkerOpts = -lhuks_ndk.z`
  （产物 `DT_NEEDED` 已有断言）。
* `HuksCredentialStore` 实现共享层 `CredentialStore`；编解码**复用** `CredentialCodec`；
  密钥由 HUKS 生成（AES-256-GCM，取不出密钥本体），密文容器 `SKB1|nonce|tag|body`。
* 实测：`huks_encrypt_decrypt_roundtrip` 明文 47B → 密文 81B → 解回逐字节相同；
  **`credential_restart`**：次轮 `load()` 读回上一轮写下的 `device_id`（HUKS 解密成功
  ⇒ 密钥与密文都跨进程存活）。

### 三个实测坑（都写进了代码注释，别重踩）

1. **cinterop `.def` 只认 `#` 注释**。用 `//` 会被粘成 `package=//=huks`，Kotlin 侧永远解析不到包名。
2. **`.def` 里不能用 `-I<sysroot>/usr/include` 直接引 HUKS 头**：本 fork 的 cinterop 会**静默退出 0
   并产出空包**（`package huks {}` 空），报出来的是 `Unresolved reference: huks`。改为把 4 个头
   **逐字节复制**进 `knspike/src/nativeInterop/include/`（`bash scripts/harmony.sh sync-huks-headers` 可重新同步）。
3. **cinterop 只能建在 compilation 上**：`kotlin.sourceSets.getByName("ohosArm64Main").cinterops`
   报 `Unresolved reference: cinterops`，要写 `ohosArm64Target.compilations.getByName("main").cinterops.create(...)`。

### 顺带修掉的一处自伤（探针把证据删了）

`credSelfTest` 第一版在结尾**无条件 `clear()`**，于是次轮 `load()` 只能拿到 null，
`credential_restart` **永远不可能 PASS**，而报告里它显示成 FAIL（像是 HUKS 有问题）。
现在 `clear()` 只在显式 `reset=1` 时验。

  `shell`(uid=2000) **写不进**的（实测 `Permission denied`），`param set` 也被拒（errNum 1001）。

### 判据被"最后一行的假绿"掩盖过（本轮最值得记的一条）

第一版 `net` 动作的判定写成"只看最后一段 H3 报告的首行"，于是 `H3 FAIL 2/3` 与 `H3 PASS 3/3`
**同时存在**时脚本仍报 ✅。真实缺陷：`transport_refuses_404` 的期望码是 404（非 2xx），
而 `h3Probe` 无差别地对每个探针都断言 `__body`/`__fields` —— 404 响应体里没有 `device_id`，
`__fields` 必然 FAIL。修了两处：① 判据只对 2xx 期望值断言 body/fields；
② 脚本改为取**全部**头部行并显式拒绝任何一段 FAIL。与 H6 的"`cos<0.95` 就算过"同源：
**判据本身的写法要被当成待测对象**。
