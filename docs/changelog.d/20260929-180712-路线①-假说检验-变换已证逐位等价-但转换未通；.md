## 2026-09-25（路线① 假说检验：变换已证逐位等价，但转换未通；并查出一个复现性缺口）

- **新增 `scripts/model_to_ms_maskfree.py`**：把掩码链从静态图里摘掉——重接 4 处
  `attention/self/Add` 的掩码输入到全零常量，再做**迭代死代码消除**自动清链（不手写删除清单，
  避免漏删）。结构结果：**331 → 285 节点**（删 46 个）。

- **等价性已证（关键）**：
  - **关闭 ORT 图优化**时，原图与变体输出**逐位完全相同**（最大绝对差 `0.000e+00`）；
  - 默认优化下差 `5.2e-06` —— 那是 ORT **融合/调度改变浮点归约顺序**，**不是语义差异**。
    把这两者分开很重要：不区分就会把"融合噪声"误判成"变换有错"（我第一版就差点这样）。
  - **等价边界**：全零 additive mask 只在「无 padding」时严格等价；带 padding 必然不同
    （脚本 `--check-padded` 把它量化出来而非掩盖）。故该变体**仅用于诊断**，生产须由宿主喂入掩码。
  - 前置事实也已验证：全 1 `attention_mask` 下四层 additive mask 均为 `(1,1,512,512)`、**恒为 0**、四层相同。

- ⚠️ **但转换失败**：`converter_lite --fmk=ONNX --modelFile=ms-static-nomask.onnx`
  报 `SetMetaGraphInput failed` → `Convert to meta graph failed`（带/不带 `--inputShape` 都失败）。
  **所以"删掉掩码链能否消除 0 CPU 挂起"这个假说仍未被检验**——连 `.ms` 都没产出。

- ⚠️⚠️ **顺带查出一个复现性缺口（独立于路线①也很重要）**：产出 `bge-static.ms` 的那条转换调用
  **没有固化在任何脚本里**（`model_to_ms.sh` 只有动态那份的 `convert`），
  即**现有 `bge-static.ms` 无法从仓库复现**。对 M7 这是实质风险：一个"能转换成功"的配方若只存在于
  某次手工操作中，后续任何人都无法重建。**下一步应先找回并固化这条配方**，再谈要不要删掩码链。

- 说明：本次转换尝试中我的临时脚本有一处引号 bug（`--inputShape` 的值含 `;` 被外层 shell 拆开），
  不影响上述结论（不带该参数时同样失败），但记录在此以免误导后来者。
