## 2026-09-25（闭合复现性缺口：静态 `.ms` 的转换配方已固化并可复现）

- **上一轮记录的缺口**："产出 `bge-static.ms` 的配方没固化在脚本里" → 本轮查清根因并修好。

- **根因（比"手工操作没记录"更具体）**：`model_to_ms.sh` 的 `convert` **硬编码转动态那份 ONNX**
  （`bge-small-zh-v1.5-ms.onnx`）。于是 `all`（fetch→rewrite→convert→check）
  **永远不会产出 `bge-static.ms`**——**脚本跑一遍复现不出它自己的关键产物**。

- **证据（时间戳判定因果）**：`ms-static-1x512.onnx` 与 `bge-static.ms` 同为 **2026-09-22 17:39**，
  产物 **94,808,432 B**，与 RFC §10 E11 记录的"`CONVERT RESULT SUCCESS:0` 产出静态 .ms（94,808,432 B）"
  完全一致 → 静态产物确实由静态 ONNX 转换而来。

- **修法**：`convert` 参数化（source/output）+ 新增 `convert-static`：
  `bash scripts/model_to_ms.sh convert-static`

- **复现验证**：重跑后产出 **94,808,432 B**、魔数 `MSL2`，与既有产物**大小完全一致**；
  当前 sha256 = `1f071d3a2f75093b…702890`。

- **同时更正一处会误导的过时结论**：`apps/harmony/README.md` 原写"固定 shape（带 --inputShape）
  → **转换阶段就失败**"——那是**四步重写完成之前**的状态，会让人误判这条路走不通。已改为
  "✅ 转换成功（94,808,432 B / MSL2），但 benchmark 0 CPU 挂起"，并把旧行标为已过时。

- 📌 **支持掩码链假说的旁证**：转换静态 ONNX 时反复报 `/m/ConstantOfShape infershape failed!`
  （**非致命**，转换仍成功）——`ConstantOfShape` 正是掩码链里的算子。不能证明挂起由它引起，但方向一致。
