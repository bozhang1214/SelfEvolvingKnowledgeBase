## 2026-09-22（集成文档全量审计（10 篇）：修正 SSE 令牌机制误判 + 21 条待办）

- **背景**：owner 要求"跟着文档做就能完成对接"。对 `jobcopilot/docs/integrations/` 下
  **10 篇**文档做了逐篇审计（10 个并行 subagent，各自对照仓库代码核实，只报"读者会怎么失败"）。

- **本轮最重要的发现：审计推翻了我自己上一轮的结论。**
  我上轮写"千帆无法 BYOK，但仍能用 `self_check` / `list_prompt_packs`"——**错了**。
  机制已亲自核实（`mcp/client/sse.py:84`）：SSE 传输先发 `endpoint` 事件宣告消息端点，
  客户端用 `endpoint_url = urljoin(配置的 url, endpoint 事件内容)` 推导消息地址；
  服务端宣告的是 `/jobcopilot/sse/messages/?session_id=...`（**不带令牌**），
  而 `urljoin` 会用它的 query **覆盖**配置 URL 上的 `?token=`。
  ⇒ `POST /sse/messages/` 到了门禁是**没有令牌**的 → 401 `缺少访问令牌` →
  **连 `initialize` 都完不成**，`self_check` 同样到不了。
  `?token=` 只在 **`POST /mcp`（Streamable HTTP）**上有效（客户端把整个 URL 直接 POST）。
  - 已修正 `qianfan.md`（改成"当前根本建不起会话"+ 三条出路）与 `integrations/README.md`
    （千帆行改为"公网端点当前不可用"；索引表第 2 条那个 ✅ 改为"⚠️ 只对 `/mcp` 有效"）。
  - **教训**：`?token=` 兜底是**按传输分叉**的，不是"全局都行"。上一轮我只验证了
    `/mcp` 的三种 401/400 就下了结论，没有验证 SSE 的第二跳。
