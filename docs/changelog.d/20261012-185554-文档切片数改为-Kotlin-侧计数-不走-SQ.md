### 第三次迭代（前两次都不行，写清楚历程免得后来者重走）
| # | 做法 | 设备实测结果 |
|---|---|---|
| ① | 直接读 `documents.chunks` 列 | 恒为 `0`（轮询 4 次仍是 0）——那一列不可信 |
| ② | `LEFT JOIN chunks ... COUNT(c.id) ... GROUP BY` | **同一条查询里**一篇算出 `1`、另一篇算出 `0`（两行都在 `chunks` 表里）——聚合不自洽 |
| ③ | **先读 `chunks.source_id` 单列，在 Kotlin 里 `eachCount()`** | ✅ `[__selftest__:1,__selftest_other__:1]`，**稳定正确** |

结论：这个平台的 NDK C 绑定在"**多表 + 聚合**"这类查询上给过多次不自洽结果，
而**逐行读单列**是它最稳的用法（`all()`/`size()` 已验证可靠）。代价是多一次查询，
但文档列表不在热路径上（打开文档页才读一次）。
