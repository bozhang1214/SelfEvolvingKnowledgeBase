## 2026-09-25（修 `verify_link` 的模型检查误报：确定性选产物 + 失败自诊断）

- **现象**：上一轮同一次运行里链接检查两条 ✅、模型检查却报"包里没有模型 rawfile"，
  而磁盘上唯一的 HAP **确实含该文件**（`unzip -l` 显示 94802472 B = 可运行版）。
  **会骗人的检查比没有检查更糟**——它会让人去查一个不存在的缺陷。

- **修法**：
  1. **确定性选产物**：原 `find … -name '*.hap' | head -1` 的输出顺序**不保证**，
     陈旧/中间产物可能被选中 → 改为优先 `outputs/` 下、同目录内按**修改时间取最新**。
  2. **失败自诊断**：列出生效产物路径 + 工程内**所有** `.hap` 及其是否带模型。
     上次那条警告信息量不足以定位；报错必须够定位，否则等于没报。

- **结果**：重跑三项全过（两个 ABI 各 4 个 KMP 入口 + 模型 rawfile 在包内）。

- ⚠️ **根因判断与证据强度（不夸大）**：最可能是检查时存在**两个** HAP、`head -1` 选中了陈旧那个，
  随后 hvigor 清理只剩一个——这与"现在确定性选择即通过、当时无从复现"一致。
  但**当时那一刻的产物清单已被覆盖，属推断而非证实**。能确定的是"原选法不可靠、现已确定性与可诊断"；
  文档中把"已修好"与"根因已证实"分开表述，不混为一谈。
