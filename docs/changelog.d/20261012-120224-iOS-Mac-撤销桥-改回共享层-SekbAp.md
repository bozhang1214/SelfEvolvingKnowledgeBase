## 2026-10-26（iOS/Mac 撤销桥：改回共享层 `SekbApi`，删掉 248 行重复实现）

- **背景**：这份"桥"不是设计选择，而是**共享层缺口的替代品**。2026-10-25 实测（macOS 框架）：

  ```
  Function doesn't have or inherit @Throws annotation and thus exception isn't propagated
  from Kotlin to Objective-C/Swift as NSError ... Program will be terminated.
  Uncaught Kotlin exception: com.sekb.shared.net.SekbApiException: SEKB 500: probe-500
  Abort trap: 6
  ```

  即：服务端返回非 2xx（**token 过期 401 很常见**）Apple 侧当场 abort。为了不崩，
  Apple 侧抄了一份 248 行的 `SekbApiBridge.swift`——协议语义仍是共享的（SSE 解析/凭证/JSON 走共享层），
  但 **HTTP + 状态码 + 字段名成了第二处维护点**。主线补上 `@Throws` 后，它就该消失。

- **改动**：
  - **删除 `apps/ios/App/SekbApiBridge.swift`（248 行）**，新增
    `apps/ios/App/SekbApiShim.swift`（**只做 `throws → Result` 转换，不含协议知识**；
    判据写在文件注释里：**里面一旦出现 `/api/v1/` 或字段名字符串就说明退化了**）。
  - `SekbContainer` / `SekbViewModel` 改走 shim；协议路径、请求体、SSE 解析、字段名重新**只有一份**（共享层 Kotlin）。
  - 自检项从"桥能跑通"改成"**共享层真的能在 Apple 侧跑通**"：
    `shared_login_token_fields` / `shared_enroll_credentials` / `shared_sse_events` /
    `shared_route_event_reported` / **`shared_http_error_is_catchable`**（最后一条就是"`@Throws` 被去掉就会红"的守卫——
    去掉后非 2xx 会退化成 `Abort trap: 6`，自检汇总行根本不会打印）。
  - 生成的 ObjC 头提供了**可复核的契约证据**：
    `- (NSString * _Nullable)loginEmail:... error:(NSError **)error` +
    `@note This method converts instances of SekbApiException to errors.`

- **验证**（两端各自复跑，非转述）：
  - `bash scripts/ios_app.sh run` → **`SEKB_IOS_SELFTEST PASS=42 FAIL=0 SKIP=1`**；
  - `bash scripts/mac_app.sh run` → **`SEKB_MAC_SELFTEST PASS=42 FAIL=0 SKIP=1`**；
  - 关键明细：`shared_http_error_is_catchable — 401 → 捕获到的 code=401 domain=KotlinException（进程存活）`。
  - `bash docs/tech/.validation/doc_guard.sh --no-warn` → 7 项全过。

- **过程中撞到并修掉的三件事（都写进代码注释）**：
  1. **Kotlin 默认参数不跨语言**：`SekbApi(transport:baseUrl:now:)` 三个都必须显式给，
     且 `now` 的返回类型是 `KotlinLong`（要 `KotlinLong(longLong:)`），否则编译报
     `missing argument for parameter 'now'` / `cannot convert Int64 to KotlinLong`。
  2. **`reportRouteEvent` 也标了 `@Throws`** → Swift 侧必须 `try`（这正是"契约生效"的体现）。
  3. **截断取样当断言 = 假失败**：路由事件请求体截到 80 字符时 `escalated`/`input_tokens` 落在后面，
     一条本应 PASS 的断言被判 FAIL。改成断言**整个请求体**——截断取样会把"字段顺序"变成隐含契约。

- **顺带修掉守卫自己的一个假阳性**：`check_protocol_paths.py` 的 `PATH_RE` 用 `*` 允许"裸前缀"，
  于是文档里"这里出现 `/api/v1/` 就说明退化了"这句话被当成"客户端调了 `/api/v1`"而报错。
  已改成 `+`（前缀后必须至少一个字符）。**反向验证**：注入 `api/v1/edge/bogus` → 守卫仍报 2 处并退出 1。
