## 2026-09-24（Android 真机验收：Mate 40 Pro 跑通，并修掉 2 个真机才暴露的缺陷）

- **背景**：owner 的手机（`NOH-AN00` / HarmonyOS 4.2 = Android 12 基座）**不能**跑鸿蒙 NEXT 的 HAP
  （见 RFC §10 E13），但正好能当 **Android 真机**用——而 RFC 风险项 **R8「无真机」** 一直是缺口
  （性能结论只能靠模拟器外推）。本轮把 Android 端真正装到真机上跑通自检。

- **真机结果**：自检 **PASS=20 / FAIL=1 / SKIP=7**；关键性能数字：
  **端侧 LLM TTFT 81 ms**（`plane=edge`，真实生成 44 字符）、**端侧嵌入 3 ms/条**（ONNX int8，512 维）、
  **检索 3 ms**、命中 `doc-rag` 分 **0.690**、SQLite 索引跨进程存活（启动时已有 3 块）、
  工具调用 JSON 合法。装法见 `apps/android/docs/VERIFICATION.md` §1.1。

- **修掉两个"只有真机才会暴露"的缺陷**：
  1. `scripts/android.sh` 的 **`install` 分支不传 `-P` 属性**（只有 `assemble` 传）→
     `SEKB_EDGE_URL=... bash scripts/android.sh install` 被**静默忽略**，`installDebug` 复用旧
     BuildConfig（仍是模拟器专用的 `10.0.2.2`），真机上表现为"端侧全部连不上"，
     而错误信息里完全看不出"环境变量没生效"。已改为 assemble/install **共用同一组 `PROP_FLAGS`**，
     并打印实际生效的属性。
  2. `SelfTest` 的 `privacy_device_only_local_gate` 把 **`blockedEdge.calls == 0`** 当成
     "本机/非本机"两分支的**共同**前置条件 → 本机端点下编排器**正确地**执行了 DEVICE_ONLY（`calls=1`）
     却判 FAIL。**后果比表象严重**：这条自检因此**只能在非本机端点通过**，也就是在模拟器
     （`10.0.2.2`）上一直"**因为错误的原因通过**"，R10「本机允许执行」那一半**从未被真正跑到过**。
     已改为按端点分档断言。

- **验证**：`bash scripts/android.sh test` 全绿；`doc_guard` 6/6；
  真机自检日志（30 行）逐项核对；`adb devices` / `getprop` / `run-as` 均为真机实测输出。

- **仍未完成（如实）**：① 上面第 2 条的修复**尚未在真机上复跑确认**——重装卡在设备侧安装确认
  （华为需要在手机上允许"通过 USB 安装应用"或解锁手机点确认框），需 owner 操作一次；
  ② 7 个 SKIP 中 `cloud_login`/`policy_*` 缺前置条件（账号/策略包），`rag_import_*` 已通过 push-sample 消掉。
