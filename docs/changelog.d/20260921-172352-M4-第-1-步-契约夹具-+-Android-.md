## 2026-09-21（M4 第 1 步：契约夹具 + Android runner（32 case / 186 测试绿，含防假绿接线））

- **背景**：四端行为一致不能靠"抄得仔细"。M4 的第一步就是把"一致"变成**可执行的夹具**：
  同一份 JSON，四端各跑一遍，结论必须相同。选它当第一步，是因为后面所有重构（抽 `shared/`、
  去平台化、Kotlin 升级）都需要一条"不许变"的护栏。

- **改动**：
  - 新增 `apps/contract/`（语言无关夹具，单一事实源）：
    `routing.json`（10 case：端侧优先 / 短任务档 / 输入预算临界 150 与 170 份重复 / 输出超预算 /
    `prefer_cloud` / `device_only` 两种入口且压过 prefer_cloud / 质量档 / 512 边界）、
    `signals.json`（14 case：6 类信号 + 退化**行数临界**（2 行不算、3 行才算）+ 前缀阶段必须排除
    `json_invalid` + 干净输出）、`privacy.json`（8 case：DEVICE_ONLY × 6 类信号，**信号命中但升级被拦**）、
    `README.md`（格式约定、各端接法、runner 的五条硬要求、覆盖与后续计划）。
  - 新增 `apps/android/app/src/test/kotlin/com/sekb/ondevice/ContractFixturesTest.kt`（4 个测试）：
    三条"防假绿"要求（夹具缺失即失败 / case 数低于下限即失败 / 6 类信号必须被覆盖）
    + 逐 `id` 断言（失败信息带 id）。长文本用 `{"repeat": {...}}` 展开，夹具里不贴几千字。
  - `apps/android/app/build.gradle.kts`：**把夹具目录登记为单测输入**
    （`inputs.dir(contractDir)` + `-Dsekb.contractDir`）。

- **验证（本轮最有价值的一条）**：
  1. 全量 **186 测试通过**（原 182 + 契约 4），`bash scripts/android.sh test` 3 秒；
  2. **可证伪**：把 `cloud.input_over_budget` 的期望从 `cloud` 改成 `edge` → 立刻红
     （`ContractFixturesTest.routing fixtures match client router` 失败），还原 → 回绿；
  3. **过程中发现一个真漏洞（"假绿"）**：夹具是运行时读的 JSON，Gradle 不把它当输入 →
     只改夹具不改 Kotlin 时 `testDebugUnitTest` 判 UP-TO-DATE **不重跑**，于是"把期望改成相反值"
     会静默通过。第一次做可证伪验证时就撞上了（改完夹具仍 BUILD SUCCESSFUL）。
     修法如上（`inputs.dir`），修完后同样改动能正常复现失败。这条已写进 `apps/contract/README.md`
     作为**新端 runner 的强制要求**。
  4. 夹具自身也抓到我一个错假设：3 行相同的退化样本我写成 35 字符，低于 `DEGEN_MIN_LEN=40`，
     测试当场报错 → 改成 20 字 × 3 行，并补了一条"2 行相同不算退化"的临界用例。
