- **起因**：准备推进 M7 路线判定时复查 MindSpore Lite 运行期，发现此前记录与实测不符。

- **更正后的实况**（两个产物此前被混为一谈，必须分开）：
  | 产物 | 行为 |
  |---|---|
  | `bge-small-zh-v1.5.ms`（**动态** shape） | `benchmark` **快速失败**：`FindBackendKernel return nullptr, name: /m/Flatten, type: Flatten` → Build failed |

  脚本头部原先写的"固定 shape 在**转换阶段**就失败"是**更早的状态**（后来转换已修好）；
  而"600s 无输出"被记成原因不明，实为 **0 CPU 的真挂起**。

- **补上的覆盖缺口**：原 `check` 只跑**动态**那个产物，**从没人在 `bge-static.ms` 上跑过 benchmark**
  （只验过它能转换、余弦对）。现 `check` 已参数化并新增 `check-static`：
  `bash scripts/model_to_ms.sh check-static`。

- **对 M7 的含义（谨慎表述）**：**Linux-aarch64 runtime ≠ 鸿蒙 runtime**（鸿蒙用系统自带
  `libmindspore_lite_ndk`，其算子集可能含 Flatten kernel），不能直接断言鸿蒙上也不行；
  但 `bge-static.ms` 的 **0 CPU 挂起是图/模型层面**的问题，大概率同样复现。
  性价比排序仍倾向 ①彻底消除动态掩码子图 / ②回 ONNX Runtime / ③退路线 B（37 条契约夹具）。
