## 2026-10-26（RDB 摆动的真因：**探针与会话抢同一个库**；单句柄注入 + 探针默认关闭）

### 对照实验（这轮最硬的证据）
把自检里的 RDB 探针**关掉再跑**，同一份代码、同一台模拟器：
```
探针开: [FAIL] rag_ingest — 列表里 1 篇（总片段 2 段）｜登记 [__selftest__:0]
探针关: [PASS] rag_ingest — 列表里 2 篇（总片段 0 段）｜登记 [__selftest__:1,__selftest_other__:0]
        [PASS] rag_retrieve — 首条=__selftest__@0.696；库里 2 行，两行 norm=1.0000
```
⇒ **那个探针本身在干扰会话**：它会在**同一个 `databaseDir`** 上再开一个 RDB 句柄，
于是会话的写入与探针的读写互相干扰，把 `rag_ingest` 从"2 篇/2 段"打成"1 篇/0 段"。
**我前面几轮反复看到的"同一份代码结果来回摆"，有相当一部分是自伤**（探针自己造成的）。

### 两处修复
1. **单句柄注入**：`RdbVectorStore` 原来**总是自己 `RdbStore.open()`**，同一个库文件上会出现多个句柄
   （会话一个、每次构造又一个、探针再一个）。改为**支持注入外部连接**（`injected: RdbStore?`），
   `SekbApp.open` 只开一个句柄并注入进去。**原则写进注释：全进程每个库只持有一个句柄。**
2. **探针默认关闭**（`skipProbe = true`）：它的价值在排查期，**不该污染常规自检**；
   需要时改成 `false` 再跑。探针同时改用**独立目录**（`$databaseDir/../probe`）——
   顺带解释了那条 `14800037`：**同一目录上再加一个新库名**在该实例上建不出来，换独立目录就正常。

### 仍未收敛的最后一点（范围已很小，且**只在自检语料上**）
同一个 `LEFT JOIN chunks ... COUNT(c.id)` 查询里，一篇文档算出 `chunks=1`、另一篇算出 `0`
（而 `chunks` 表里两行都在、`rag_retrieve` 也能同时看到两行）——**同一查询内的聚合结果不自洽**。
这也是 `rag_delete` 报"删 0 段、删前 0 篇"的来源。它属于同一个平台级的读一致性抖动，
**只影响自检里那两个派生计数**，不影响：真实 UI 路径的导入/列表/检索（本轮已 PASS）、
嵌入与打分（上轮已用直接余弦证明正确）。
