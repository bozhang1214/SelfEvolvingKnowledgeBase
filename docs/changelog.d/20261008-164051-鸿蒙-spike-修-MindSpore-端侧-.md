## 2026-10-08（鸿蒙 spike：修 MindSpore 端侧 double free 崩溃（推理跑通））

- **背景**：鸿蒙 spike 的 MindSpore Lite 端侧嵌入走到 `-5 → -7 → -3100 → 崩溃`，
  README 里记的下一步是"取 cppcrash 看栈"。拉下 `/data/log/faultlog/faultlogger/` 后，
  栈是**析构路径**且 musl 报 **double free**：

  ```
  LastFatalMessage: This is an unexpected memory usage behavior. may double free
  Tensor::FreeData → Tensor::~Tensor → LiteSession::~LiteSession → Graph::~Graph
    → OH_AI_ModelDestroy → libkn.so → sekb_spike_mindspore_selftest → Index.ets:52 runModel
  ```

- **根因**：`MsLite.kt` 里三处把 **`memScoped` 分配的缓冲**交给 `OH_AI_TensorSetData`——
  该接口会把指针交给张量（内存归张量所有，析构时 free），而 `memScoped` 离开作用域
  **已经 free 过一次** → 两种所有权模型相撞 = double free。**不是** dtype/尺寸错配，
  也不是读输出越界（README 之前列的两个猜测都不是）。

- **改动**：新增 `fillI64` / `fillF32`，改为写 `OH_AI_TensorGetMutableData` 返回的
  **模型自有缓冲**（`predict` 与 `predictTyped` 共三处调用点），顺带删掉不再需要的
  `OH_AI_TensorSetData` / `allocArray` / `CPointer` 导入与"必须同 memScoped"的旧注释。

- **验证**（模拟器，`hdc` 全流程实测）：
  - `bash scripts/harmony_spike.sh all` → exit 0；`hdc install` → successfully；
  - `aa start` 后 hilog：**`mindspore selftest elemNum=262144 firstFloat=173347`** ✅
    （elemNum 为正即成功分支；firstFloat 是真实非零输出）；
  - 进程存活、**`faultlogger/` 无新增崩溃文件**；
  - 即 **MindSpore Lite 端侧嵌入第一次在 OHOS 上完整算完并取到向量**。

  `OH_AI_TensorSetData` 写法；它未编入构建，所以本次验证覆盖不到，**启用前必须一并改**。
