### 为拿到它做的四件事（都值得记）
1. **接出 `rag_step` 的 NAPI 入口**：`sekb_spike_rag_step` 一直只有 Kotlin 实现、**没有 NAPI 入口**，
   所以"分步跑评测"这条早就设计好的路从未被用过（整段同步 ~90s 会撞 `THREAD_BLOCK_6S`）。
   入口仍加在 `h3h4_napi.cpp`（**`napi_init.cpp` 主线独占**，不挤进去）。
2. **分步评测也走文件型存储**：`RagAcc` 增加 `filesDir`，并抽出**顶层** `newStoreFor(...)`
   （原来 `newStore` 是 `RagAcc` 的私有方法，导致整段版里还有两处**硬编码 `RdbVectorStore`**——
   换实现时漏改就是"测的不是新实现"的隐蔽假失败，本轮真踩过）。
3. **引入组合接口 `VectorAndDocumentStore`**（`VectorStore + DocumentRegistry + openDiagnostics + dbNamePublic`）：
   两个实现类本来就同时实现两个父接口，但变量只声明 `VectorStore` 时**看不到 `list()`**（编译期就报）。
   有了组合接口，调用处**不必在"文件型 / RDB"之间分支**。
4. **修一个"测试自己没跟着实现切换"的假失败**：持久化断言里硬编码构造 `RdbVectorStore`，
   在文件型后端下测的其实是 RDB（新库当然是空的）→ 误报"没落盘"。

### 同时修掉的两个真缺陷（都写进注释）
- **`save()` 不检查 `rename` 的返回值**：于是"数据没落到目标文件"是**静默**的。
  现在 `rename` 失败直接抛错（附 `errno`），并记录 `lastSaveInfo` 供自检展示。
- **路径被拼了两次前缀**：`dbNamePublic` 返回的已经是**文件全路径**，而无条件拼
  `"$filesDir/$name"` 会得到 `…/files//data/storage/…/files/x.db` 这种双前缀路径——
  `access()` 说"存在=true"（在真路径上），而重开读的是那个不存在的双前缀路径 → 又一处静默失败。
  判据：`name` 以 `/` 开头就当全路径。
- `stepEval` 的 `return` 早退 → 五档表在下一份报告里被丢掉，**从来没被打出来过**；改为不早退。
