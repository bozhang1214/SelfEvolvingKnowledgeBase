## 2026-09-24（深色模式修复：42 处硬编码色改走主题 + 新增配色纪律机械检查）

- **背景**：上一轮我承诺"深色模式只定义了配色、没在真机上验"。本轮准备补验时手机已断开 adb，
  于是改为**代码层核查**——结果发现比"没验"更糟：**"我定义了深色配色"这句话根本不成立**。

- **查到的缺陷**：`SekbTheme` 里有 `DarkScheme`，但三个页面**42 处硬编码** `SekbColors.*` 常量
  （`Fill #F0F2F5` 近白、`PrimaryContainer #E6F0FF` 近白蓝、`Border #E5E7EB`、`Primary #1677FF`），
  **页面根本没走主题**。深色下后果：输入框与头像变**白块**、空状态变**白圆**、边框在深底上几乎看不见。

- **改动**：
  - 页面里的主题色一律改走 `MaterialTheme.colorScheme.*`。
  - 语义色（本机完成=绿 / 已上云=金 / 失败=红）改为 `SekbSemantic` + `LocalSekbSemantic`，
    **明暗两套**（深色下提亮，否则糊在背景里）。
  - `MarkdownView.inlineText()` 非 `@Composable`，行内码底色与链接色改为**显式参数**
    （直接读 `MaterialTheme` 编译不过）；顺带把隐式主题读取变成显式契约。
  - 新增 `ThemeColorDisciplineTest`（2 条）：页面不许出现 `SekbColors.`（`theme/` 豁免，
    注释不算，扫描文件数 <3 判失败以防"目录找错→静默通过"）；纯逻辑文件不许 import Compose。

- **验证**：
  - `bash scripts/android.sh test` → **258 用例 / 0 失败**（+2）。
  - **验证守卫真的会失败**：注入一处 `SekbColors.Primary` → `FAILED` 且精确指到 `ChatScreen.kt:128`；
    还原 → 回绿。（仓库既有做法：一个不能失败的检查等于不存在。）
  - `grep 'SekbColors\\.' ui/*.kt | grep -v SekbTheme` → 空。
  - ⚠️ **仍未做**：深色模式的**真机目视确认**（验证时手机已断开 adb）；代码层已对齐，
    但"看起来对不对"仍需一次真机截图。已记入 VERIFICATION §1.4。
