## 2026-10-08（四端验收总入口 `scripts/verify_all_ends.sh`：一条命令看清四端到哪了）

- **背景**：端侧现在有四条验收线（Android / iOS / Mac / 鸿蒙），各有自己的脚本与"验证记录"，
  但**没有一个地方能一次跑完并给出总表**。后果有两类，都是本仓库真实发生过的：
  ① 每次汇报要手工拼数字 → 拼错就变成 `fact:android_unit_cases=231` 那种漂移（实测 291）；
  ② 新接手的人不知道该先跑什么，只能从 README 里一行行抄命令（"恢复指引"因此越写越长）。
  本轮是"四端收口"开工，**先把验收入口收成一个**，再让三端并行动手。

- **改动**：新增 `scripts/verify_all_ends.sh`，两种模式：
  - **`quick`（≈45 秒，本机实测）**：文档守卫 7 项（含第 7 项端侧活数字）、端侧活数字 ↔ 实测、
    共享层 `:shared:compileAndroidMain` 可编、Android 单测计数（`@Test` 静态计数 **↔** Gradle XML 报告交叉验证）；
  - **`full`（分钟级）**：Android 单测全量、iOS framework+Swift 冒烟、Mac 自检、鸿蒙 KMP+interop 冒烟；
  - 输出**逐项 PASS/FAIL/SKIP + 原始命令 + 日志路径**；**SKIP 必须写清缺什么**，
    且只有环境限制类（缺 Xcode / 缺 ORT / 依赖仓库不可达）才允许 SKIP；退出码只反映 FAIL。

- **验证**（本机实测）：
  - `bash scripts/verify_all_ends.sh quick` → **4/4 PASS**（`doc_guard` 7 项、`android_unit_cases` 291、
    `:shared:compileAndroidMain` BUILD SUCCESSFUL、静态计数 291 == XML 报告 291、契约夹具 37 case）；
  - `full` 模式的各端分支与既有脚本 1:1（`android.sh test` / `ios.sh smoke` / `mac_app.sh run` /
    `harmony.sh smoke`）；鸿蒙分支在 `smoke` 动作尚未落地时**如实记 SKIP 并写明"H1 未完成"**，不伪装通过。

- **踩到并记下的坑**（都写进脚本注释）：
  1. 直接调 `apps/android/gradlew` 会报 `Unable to locate a Java Runtime` —— 必须先按
     `scripts/android.sh` 的口径导出 `JAVA_HOME`（脚本里做成 `prepare_android_env`）；
  2. `apps/shared` 的编译任务名是 **`:shared:compileAndroidMain`**（AGP 9 KMP 插件命名），
     写 `compileDebugKotlinAndroid` 会报 task not found；
  3. `set -u` 下 `$log（中文括号` 会被当成变量名（多字节首字节按字母处理）→ 变量一律写 `${log}`。
