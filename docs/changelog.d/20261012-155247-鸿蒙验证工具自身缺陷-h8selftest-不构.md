## 2026-10-26（验证工具自身两处缺陷：`h8selftest` 测的是**旧包**；RDB 打开缺重试）

这一轮的产出主要是**把"验证工具在骗人"这件事修掉**，其次是继续缩小 RAG 的根因。

### ① ⚠️ `scripts/harmony.sh h8selftest` 原来**不构建、不安装**
只 `aa start`。后果：改了 ArkTS/Kotlin 之后跑自检，取的其实是**上一次装上去的旧包**，
而旧包会安静地给出旧结论。本轮实测踩到——我给 `rag_retrieve` 加了 4 个诊断字段，
跑出来却**完全没有那些字段**；查 HAP 时间戳才发现包是 1 小时前的。
**这类"检查工具自己在骗人"比被测代码出错更危险**（会让人对着旧现象查半天，本轮就白绕了几轮）。
已修：动作开头构建（`harmony_spike.sh all`，失败即 `die` 并指向构建日志）+ 安装，
再启动自检。**凡是要跑设备侧验证的动作，都必须先构建+安装**。

顺带记一条同源教训：本轮另有一次 ArkTS 编译错误（`Cannot find name 'TAG'`，我在新代码里用错了常量名）
——因为脚本当时不检查构建结果，**编译失败也照样"跑"出了旧包的结果**。现在构建失败会直接中止。

### ② `RdbStore.open` 加 3 次重试（平台装包/首启后的就绪竞态）
现象：刚 `hdc install` 完（或换新模拟器实例）时，第一次 `OH_Rdb_GetOrOpen` 返回
`14800037 = RDB_E_CREATE_FOLDER_FAIL`，**同进程随后重试就成功**；`databaseDir` 存在且可写
（`ensureDatabaseDir` 会先建父目录+目标目录并复核）。所以这不是路径问题，而是平台侧 el2 存储区
在装包/首启后**尚未就绪**。改成重试 3 次、间隔 120ms，并把**最后一次的 errCode 原样返回**（不吞错）。
实测：加完之后 `rag_store_open` 由 FAIL 转 PASS（装包后立即跑也是 PASS）。

### ③ RAG 的根因继续缩小（已到"检索侧"，不再是"写入侧"）
```
[PASS] rag_store_open      — RDB 自检库已打开（隔离库）
[PASS] rag_ingest          — 导入「__selftest__」→ 列表里 2 篇（总片段 2 段）   ← 切片真的进库了
[PASS] rag_delete          — 返回 0 段；剩余 1 篇（删前 2），别的文档还在=1      ← 登记/删除也对
[FAIL] rag_retrieve        — 检索 → 0 条 reason=below_threshold:最高分=0.000<0.4
                             space=BAAI/bge-small-zh-v1.5@512 cloudCompatible=true
                             嵌入=0ms 检索=0ms
```
关键新事实：**`最高分=0.000` 且嵌入/检索耗时都是 0ms** —— 说明这次检索**根本没算出分数**
（要么检索时用的嵌入给出**全零向量**，要么候选集为空）。而 `chunks` 表**确实有数据**（总片段 2 段）。
另外 `dbChunks=-1 / allRows=-1` 说明我加的"写入后回读"在 `RdbVectorStore.size()/all()` 上**抛了异常**
（`documents()` 却正常工作）——这两条指向**同一处：`chunks` 表的读取路径**（`RdbVectorStore.all()`
/`size()` 的 cursor 读法），而不是写入。
→ **下一轮的第一件事**：给 `RdbVectorStore.all()/size()` 的异常补上原因（把 `runCatching` 的
`exceptionOrNull()` 消息带进返回值），再看 `Retriever.retrieve` 的 `embedMillis=0` 是"没嵌入"还是
"嵌入返回全零"——两条都能一眼分辨"写/读/嵌入"三选一，不必再猜。
