- **验证**（实测）：
  - `bash scripts/harmony_spike.sh hap` → `BUILD SUCCESSFUL`，产出
    `entry-default-unsigned.hap` **4.8M**（未签名，符合预期）。
  - HAP 内 `libs/{arm64-v8a,x86_64}/` 同时含 `libknspike.so`（NAPI）与 `libkn.so`（KMP）；
    `llvm-nm -D --undefined-only` 确认 `libknspike.so` 里 `sekb_spike_ping` / `sekb_spike_echo_len`
    均为 **`U`**（undefined），即**加载期由同包 libkn.so 解析**——两 ABI 各 2/2。
  - **口径声明**：本条只证明到"产物齐备且 NAPI↔KMP 引用成立"；"能装能起 + 真的调通"
    属于第 4 条，需要签名 HAP + 设备/模拟器。脚本把这句话直接打在输出里，避免将来被误读成"已经跑通"。
  - 三个实测坑写进脚本注释：hvigor 默认写 `~/.hvigor`（EPERM）→ `HVIGOR_USER_HOME`；
    hvigor 会 `npm install -g pnpm`（EPERM）→ `HOME`/`npm_config_*` 收进仓库；
    `PackageHap` 需要 JDK（失败发生在 native 编译**成功之后**，极易误判）→ `JAVA_HOME=$DEVECO/jbr/Contents/Home`。
  - 另两个细节：`EXTERN_C_START/END` 不在 NAPI 头里（需自定义）；Kotlin `String` 参数在 C 侧
    就是 `const char*`（以生成的 `libkn_api.h` 为准）。
