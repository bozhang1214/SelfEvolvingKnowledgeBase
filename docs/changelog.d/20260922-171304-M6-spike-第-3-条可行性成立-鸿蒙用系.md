## 2026-09-22（M6 spike 第 3 条可行性成立：鸿蒙用系统 MindSpore Lite，不自建 ORT）

- **背景**：spike 第 3 条原验收是"ONNX Runtime 自建跑通嵌入"，此前一路撞在 GitHub 不可达上
  （ORT 源码在 github.com，镜像仓库又只有移植补丁、没有预编译产物）。复核工具链后确认
  **方向本身就错了**：Kotlin/Native 的 OHOS 工具链已预置 HarmonyOS 的 MindSpore Lite 平台绑定。

- **改动**：
  - 新增 `apps/harmony/spike/knspike/src/ohosMain/kotlin/MindSporeProbe.kt`：用
    `platform.MindSporeLiteKit.MindSpore` 真实创建/配置/销毁一个 MindSpore Lite context，
    并让 `OH_AI_TensorHandleArray` 结构体参与编译——目的是把 `OH_AI_*` 符号真的带进产物，
    从而能在 `.so` 上做产物级验证（而不是只"看起来能 import"）。
  - `scripts/harmony_spike.sh` 新增 `mindspore` 动作：编 `libkn.so` + 逐 OHOS 目标跑三条断言。

- **验证**（实测，两目标各一遍）：
  - ✅ 导出 `sekb_spike_mindspore_probe` / `sekb_spike_mindspore_tensor_count`（平台 klib 编译链接通过）；
  - ✅ 5 个 `OH_AI_*`（ContextCreate/SetThreadNum/DeviceInfoCreate/ContextAddDeviceInfo/ContextDestroy）
    在 `libkn.so` 里为 **weak undefined（`w`）**——不自己实现，运行时由系统解析；
  - ✅ `llvm-readelf -d` 显示 `DT_NEEDED: libmindspore_lite_ndk.so`——`.def` 的 `linkerOpts` 真的生效。
  - 两个实测细节：该平台库**不需要**写 `cinterops`（直接 import），但所有 `OH_AI_*` 都要
    `@OptIn(ExperimentalForeignApi::class)`；`OH_AI_ContextDestroy` 吃的是**句柄地址**
    （`OH_AI_ContextHandle*`），要先 `memScoped { alloc<COpaquePointerVar>() }`。
  - **口径声明**：本条只证明到"**可行性成立（编译 + 链接层面）**"。真跑嵌入需要有设备/模拟器，
    与第 4 条同一个卡点；脚本把这句话直接打在输出里。
