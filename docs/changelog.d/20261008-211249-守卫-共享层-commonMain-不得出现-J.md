## 2026-10-08（守卫：共享层 `commonMain` 不得出现 JVM 专有 API —— 带**可见豁免**）

- **背景**：`EvalStats.formatRate` 里的 `"%.1f".format(...)` 是 JVM 专有，在 `commonMain` 编不过，
  却一直没被发现——原因是**编译矩阵有缺口**：iOS/Mac 只在 `-PsekbNativeTargets=true` 时声明 native target，
  日常构建（含 CI）只编 Android 变体，于是"共享层零平台依赖"这句结论对**没被编到的部分**是空的。
  它是**鸿蒙第一次真的把共享层编到 `ohosArm64`** 时才暴露的（见同日 `EvalStats` 那条记录）。
  这类缺陷的正确防线不是"再等下一次多端编译"，而是一条 5 毫秒可跑、不需要任何工具链的静态检查。

- **改动**：`scripts/check_edge_facts.py` 新增第 ⑥ 项检查——扫描 `apps/shared/src/commonMain/**/*.kt`，
  命中 `.format(` / `printf(` / `java.*` / `javax.*` / `System.currentTimeMillis` / `System.getProperty` /
  `Locale` 即报错（跳过注释行：注释里正因为在说"这是 JVM 专有，所以不用"）。
  - **检测器刻意收窄**：第一版把普通字符串里的 `%C`（"95%CI …%"）当成 printf，报了两处假阳性——
    一次假阳性就会让人不再信任守卫，所以宁窄勿宽。
  - **逃生阀必须可见**：文件里写 `// sekb:allow-jvm-api: <理由>` 即整文件豁免，
    且豁免会**被打印出来**（`commonMain 的 JVM 专有 API：0 处（另有 1 处显式豁免）`）。
    想要的不是零豁免，而是**每一处豁免都看得见**。
  - 现有唯一豁免：`EdgePolicy.kt` 的 `formatChar`（只是命名带 format，函数体是纯 Kotlin 的
    `\uXXXX` 十六进制拼装）——已在代码里写明理由与"为什么不放宽规则"。

- **验证**：
  - `python3 scripts/check_edge_facts.py` → `commonMain 的 JVM 专有 API：0 处（另有 1 处显式豁免）` ✅；
  - **反向验证（证明它能抓住那次真实事故）**：把 `61665c4` 版本的 `EvalStats.kt`（含
    `"%.1f%%".format(...)`）临时放进 `commonMain` → 检测器命中 `.format(`；删除后回绿
    （工作区已确认无残留文件）；
  - 另有跨端交叉验证：`./gradlew -PsekbNativeTargets=true :shared:compileKotlinIosSimulatorArm64`
    → BUILD SUCCESSFUL（约 41 秒，缓存后），确认当前共享层在 iOS 侧确实编得过。
