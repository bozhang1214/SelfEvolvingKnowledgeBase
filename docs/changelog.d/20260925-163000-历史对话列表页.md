## 2026-09-25（历史对话列表页：把"已落盘但看不到"的对话变成可访问）

- **背景**：上一轮的会话持久化只做到"重启恢复**最近一次**"。更早的对话**其实已经落盘**，
  但用户看不到、也点不进去——**存了却拿不出来等于没存**。

- **改动**：
  - `ui/ConversationListScreen.kt`：列表卡片（标题 / 相对时间 / 消息条数 / 删除）、空状态、当前对话标记；
    点开即加载并回到聊天页；`ChatViewModel` 新增 `refreshConversations`/`openConversation`/`deleteConversation`。
    "启动恢复"与"列表点开"**共用同一个 `loadConversation()`**——两份实现必然漂移。
  - `ui/TimeFmt.kt`：相对时间文案（纯逻辑，9 条单测）。"刚刚 / N 分钟前 / HH:mm / 昨天 HH:mm /
    N 天前 / 日期"分段降级；**时区与当前时间都作为参数注入**，否则 CI（UTC）与开发机（UTC+8）结果不同。
  - 顶栏加历史入口（常驻）。删除不做二次确认（本地记录、无数据丢失风险，确认弹窗会让清理多条变得很烦）。

- **过程中发现并修掉一个体验缺陷**：**点「新对话」后重启会跳回旧对话**。
  发现方式很偶然——我用 `adb input tap` 点历史图标时**点偏到了「新对话」**（"+" 只在有对话时出现，
  图标位置会变），对话被清空；随后重启，**旧对话又回来了**。
  根因：启动按"最近更新的一段"恢复，而新对话是空的、没有落盘，`latest()` 只能拉回上一段。
  修法：新增**当前会话指针**（`ConversationStore.saveCurrentId/currentId`，Android 存
  `files/conversations/current.id`，**不以 `.json` 结尾**所以不会被当成会话）；无指针时退回 `latest()` 保证兼容。

- **验证**：
  - `bash scripts/android.sh test` → **285 用例 / 0 失败**（新增 `TimeFmtTest` 9 条）。
  - **真机**（Mate 40 Pro，深色模式）：历史页 `1 段 · 都存在这台设备上`，卡片
    「现在几点了？」+ **`25 分钟前 · 2 条消息`**；杀进程重开后标题与内容正确恢复；顶栏四入口布局正确。
  - `ThemeColorDisciplineTest` 的纯逻辑清单已纳入 `TimeFmt.kt`；`doc_guard` 6/6。
