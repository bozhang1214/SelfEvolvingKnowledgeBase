## 2026-09-21（M6 spike：第 1 条编译半段完成——独立构建实编 `libkn.so`）

- **背景**：spike 第 1 条是"KMP 模块能编出 ohos 产物，并被 HAP 通过 NAPI 调用"。
  本轮把**编译半段**做完并留下产物证据。

- **做法**：新建**独立 Gradle 构建** `apps/harmony/spike/`（故意不并进 `apps/android` 的构建——
  那边是 AGP 9 + Kotlin 2.2.10 且已全量验证，而 CPF fork 配套 AGP 8 + Kotlin `2.2.21-0.3.0-07`；
  混在一起就是"为了验 A 顺手把 B 弄坏"）。配置抄自官方 KMP sample：
  单一仓库 `maven.eazytec-cloud.com/nexus/repository/maven-public/`、
  `applyDefaultHierarchyTemplate=false` + 手工 `ohosMain` 源集、`cacheKind.ohos*=none`。

- **验证（实测）**：
  `./gradlew :knspike:linkDebugSharedOhosArm64 :knspike:linkDebugSharedOhosX64` → **BUILD SUCCESSFUL**
  - 产物：`libkn.so` × 2（`ohosArm64` = **ELF aarch64**；`ohosX64` = x86-64）+ `libkn_api.h`
  - 导出符号：`nm -D` → `T sekb_spike_ping`、`T sekb_spike_echo_len`（NAPI 侧按名字取）
  - 工具链：构建时自动从该 nexus 拉 **OHOS sysroot `sysroot-hms-aarch64-6.0.2.640-02`** +
    **毕昇 LLVM 19 `llvm-1914-aarch64-macos-dev-10`** 到仓库内 `.tooling/konan/`（全部在仓库内，无工作区外写）

- **踩到的三个坑**：① 空的 `kotlin.native.home=` → `Cannot convert '' to File`；
  ② `@CName` 需 `@file:OptIn(kotlin.experimental.ExperimentalNativeApi::class)`；
  ③ sample 的 wrapper 指向 Gradle **8.14.3（腾讯镜像）**，与 Kotlin fork 匹配（不要换成 9.x）。

- **仍未做的半段**：`libkn.so` 进 HAP → NAPI 调用 → **装到设备/模拟器**。
  官方文档明确"鸿蒙应用必须完成签名才能安装"，所以这半段需要 **owner 的华为开发者账号**
  （DevEco 模拟器登录 + 签名配置）。
