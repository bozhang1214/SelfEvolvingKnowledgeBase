## 2026-09-25（L1 策略热修：发现并修复两个各自致命的跨端缺陷，真机 E2E 首次跑通）

- **背景**：推进遗留项 B3（把真机自检里 3 个策略 SKIP 转正）。推上服务端签发的策略包后被拒，
  顺藤摸出两个缺陷——**各自单独就足以让 L1 策略完全不可用**，且此前所有测试都发现不了。

- **缺陷 1｜开发默认签名密钥两侧不一致**：服务端未配 `SEKB_EDGE_POLICY_SECRET` 时返回
  `sha256("edge-policy:dev-only").hexdigest()`，而端侧 `BuildConfig.DEFAULT_EDGE_POLICY_KEY`
  是原文字面量 `"edge-policy:dev-only"`；`build.gradle.kts` 的注释还写着"会派生同一个开发密钥"——
  **这句话是错的**。后果：默认配置下端侧拒绝**所有**服务端签发的策略（`policy_bad_signature`）。

- **缺陷 2｜时间单位不一致**：服务端 `expiresAt` 是 **秒**（`int(time.time())`），端侧拿它跟
  `nowMillis`（**毫秒**）比 → 实测 `1790753917 < 1790667517429` **恒真**，
  即**每一份策略都立刻被判 `policy_expired`**。

- **为什么没被发现（结构性原因）**：两侧测试都是**同侧自洽**——后端自签自验（同一个错误密钥也通过）；
  端侧用自选密钥 `"test-key"` 只验算法、且时间字面量是**秒级**的 `1700000001`，
  恰好让"秒 vs 毫秒"暴露不出来。M4.5 验收③ 因此**从未真正端到端跑通过**。

- **修法 + 新增跨端守卫**：
  - 服务端默认密钥改为字面量常量（与端侧逐字一致）；`issuedAt/expiresAt` 改为 epoch **毫秒**并写明单位契约；
  - 后端新增 `test_dev_default_matches_android_build_default`：**直接读 Android `build.gradle.kts`**
    抽默认值比对；另有 `>10**12` 单位守卫；
  - 端侧新增 `PolicyCrossEndFixtureTest`：加载**由服务端代码签出**的真实策略包并断言验签通过，
    附**反向守卫**（当年那个 sha256 派生密钥必须被判 `policy_bad_signature`）；
    夹具测试的时间**必须用真实毫秒**（第一版用了秒级字面量，"恰好"绕过缺陷 2）。
  - 已验证守卫会红：改掉端侧默认值 → 后端守卫立刻 FAILED 并打印两侧的值；还原即回绿。

- **真机 E2E（首次跑通）**：`policy_apply_rebuild` 阈值 **0.5 → 0.7**、`policy_threshold_wired` 0.7、
  `policy_rollback_restores_threshold` 回滚后 0.7；**自检 `PASS=28/0/4` → `PASS=31 FAIL=0 SKIP=1`**。
  这同时证明 **M4.5 验收③ 成立**（改阈值不发版、不重启即生效）。

- **顺带修掉 `scripts/android.sh` 三个缺陷**：`push-policy` 把任务名当文件路径（`$1`→`$2`/shift）；
  `for task in "$@"` 会把带参数调用的**文件路径当成第二个任务**去跑 `./gradlew <路径>`（改 `while`+`shift`）；
  相对路径需按仓库根解析（脚本已 `cd apps/android`）。

- **剩余**：线上 `bos-studio.tech` 仍是旧代码，需**重新部署**后"实时拉取策略"这条路径才闭环
  （本次是注入本地策略包的离线路径）。
