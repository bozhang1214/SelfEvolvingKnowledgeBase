## 2026-09-21（M5 端口④：iOS PDFKit 文本抽取——与 Android 同语义、同数字，自检 13/13）

- **背景**：文档导入是端侧的核心功能之一，而 PDF 抽取是"平台必须自己写"的端口
  （Android 用 PdfBox-Android，iOS 用系统自带的 PDFKit）。

- **改动**：
  - `apps/ios/App/PdfExtractor.swift`：`PdfTextExtractor.extract(data:)` → **四类结果**
    （`ok(text,pages)` / `noTextLayer` / `encrypted` / `failed(reason)`），
    与 Android 侧 `ui/PdfExtractor.kt` **同一套语义**：先判 `%PDF` 魔数、只抽文本层不做 OCR、
    40 万字符上限（防止超长 PDF 吃内存）。端侧没有服务端兜底，所以失败必须分类说清原因。
  - 自检新增三项（样本**直接复用 Android 的 test resources**，避免两端各造一份样本）：
    有文本层 / 无文本层 / 非 PDF。
  - `scripts/ios_app.sh`：构建时把样本文档拷进 `.app` 包。

- **验证（模拟器实测）**：
  ```
  SEKB_IOS_SELFTEST PASS=13 FAIL=0
  [PASS] pdf_extract_text_layer — 页数=1 字符=78 开头=On-device RAG keeps the
  [PASS] pdf_extract_no_text_layer — 扫描件/无文本层被如实识别
  [PASS] pdf_extract_rejects_non_pdf — 非 PDF 被拒并给出原因
  ```
  **跨端一致性证据**：Android 侧同一份样本的自检输出是「抽取 78 字符 / 1 页」——
  iOS 是「页数=1 字符=78」，**两端数字完全一致**（同一份 PDF、同一套语义）。

- **下一步（M5 端口②③）**：Keychain 凭证、ONNX/CoreML 嵌入；补齐后让 iOS 自检项与 Android 等价
  （当前 13 vs 30）+ 同一标注集检索评测、数字一致。
