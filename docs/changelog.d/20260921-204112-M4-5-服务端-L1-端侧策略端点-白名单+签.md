## 2026-09-21（M4.5 服务端：L1 端侧策略端点——白名单 + 签名 + 灰度 + 空间戳绑定）

- **背景**：端侧的一些行为参数（升级信号开关、前缀守卫长度、端侧预算、模型档位、提示词、
  工具白名单、检索阈值）不该靠发版来改；但"服务端随便下发"又会绕过版本守卫。按工程议题文档
  §3.2 的口径：**白名单 + 签名 + 空间戳绑定 + 可灰度 + 可回滚**。

- **改动（服务端）**：
  - 新增 `backend/app/core/edge_policy.py`：
    - `POLICY_KEYS` **白名单**（10 项可变项）；`validate_policy` 对**未知键整包拒绝**（不是"忽略未知键"），
      并对 `streamGuardChars`（0–400）、`retrievalMinScore`（0–1）、`maxOutputTokens` 做越界校验；
    - `build_policy`：从服务端现有端云配置推导基线 + 合并 overrides → 校验 → 版本号 = 内容哈希 →
      带 `embeddingSpace`（**空间戳绑定**）、`rollout{percent,salt}`、有效期、`deviceProfiles{}`（预留占位）；
    - **HMAC-SHA256 签名**覆盖 `version + issuedAt + expiresAt + embeddingSpace + rollout + policy + deviceProfiles`
      （键序无关的 canonical JSON）。密钥取 `SEKB_EDGE_POLICY_SECRET`，否则由 `llm.jwt_secret` 派生，
      都没有则用开发默认值并**打警告**；
    - `applies_to_device`：`sha256(deviceId:salt) % 100 < percent`（用 sha256 而非内置 `hash()`——
      后者跨进程不稳定，灰度会"今天命中明天不命中"）。
  - `GET /api/v1/edge/policy`（`backend/app/api/routes/edge.py`）：设备 token 鉴权（`get_current_device`），
    返回前**服务端自校验签名**，签名写错不必等端侧来报。
  - `deviceProfiles` 仅占位：端侧白名单校验会跳过它（"设备适配"本期不实现，owner 已定）。

- **验证**：`backend/tests/unit/test_edge_policy.py` **19 条**（字段齐全/空间戳绑定/基线来自配置/
  版本=内容哈希/未知键拒绝/越界值拒绝/保留键放行/签名正例/改策略或改 rollout 或改空间戳都失效/
  缺签名返回 False 而非抛/灰度 100% 与 0% 边界/分桶确定性与比例 0.15–0.45/换 salt 会移动分桶/
  端点端到端自校验/canonical JSON 稳定性）。
  **全量后端 990 passed**（原 971，+19）；`ruff` All checks passed；`mypy 309 ≤ 310`。
  端点表同步：`gen_facts_routes.py --write` → **84 个端点**（新增 `/edge/policy`），
  `docs/tech/05-API-REFERENCE.md` 的 `fact:api_endpoints` 已同步为 84。
