## 一、安全类（P0，建议尽快决策）

### 1. 账号接管：重置密码仅凭邮箱，无验证码
- **影响**：知道任意邮箱即可重置该账号密码，结合 XFF 限流绕过构成完整接管链。
- **方案**：A. 发邮件验证码（需 SMTP，当前 Alertmanager 邮件通道本来就是坏的）；B. 加「原密码确认」+ 仅限已登录本人；C. 验证码存 Redis（5 分钟一次性）+ 对未知邮箱返回与已知完全相同的响应（防枚举）。
- **👍 建议**：先做 B（改动最小、立即可上线，不依赖邮件/Redis），邮件验证码列为后续增强。

### 2. JWT 弱密钥兜底 + 有效期 90 天
- **影响**：`config.yaml` 的 `jwt_secret` 有已知弱默认值；token 90 天 + 前端「自动续租」≈ 永不失效，泄露后风险窗口极大。
- **方案**：A. 删弱默认、`JWT_SECRET` 缺失即启动失败（fail-fast）；B. 有效期降到 access 2h + refresh 7d（需前端配合双 token）；C. 仅缩短到 7 天（改动小）。
- **👍 建议**：A 立即做（当前生产已设 JWT_SECRET，无影响）；B 作为中期（前端改造量大，列入 backlog）。

### 3. 登出黑名单在内存，重启/多 worker 即失效
- **影响**：登出后 token 仍长期可用；容器重建后已登出 token 复活。
- **方案**：A. 迁 Redis（项目已有 Redis 用于 L2）；B. 缩短有效期（见 #2）降低黑名单必要性。
- **👍 建议**：B 先行（配合 #2 缩短有效期），A 随多 worker 一起做。

### 4. 监控栈零鉴权（Grafana admin/admin、Prometheus/Loki/Alertmanager 无认证）
- **影响**：任一端口可达即可读全部容器日志/指标（当前靠 ufw + Tailscale 挡，属单点）。
- **方案**：A. 随机强密码 + 端口绑 127.0.0.1；B. 加 nginx basic-auth 反代；C. 维持现状（依赖 Tailscale 内网）。
- **👍 建议**：A（成本低、消除裸奔）；需你确认监控当前是**怎么访问的**（Tailscale 100.71.24.105? 端口映射?），我好按你现有的访问方式改而不打断你。

### 5. 浏览器服务 Cookie 端点零鉴权 + 明文落盘
- **影响**：同 Docker 网络内任意容器可读写 BOSS 登录态，等于账号劫持；`/data/cookies.json` 明文。
- **方案**：A. 加内部共享 token（`X-Internal-Token`，backend↔browser 环境变量约定）+ 文件 `chmod 600`；B. cookie 落盘加密（Fernet）。
- **👍 建议**：A（改动小、覆盖主要风险）；B 列为后续。

### 6. 分享链接无密码/无过期/无访问审计，SSE 问答无限流
- **影响**：链接泄露即可被反复读/问，刷爆 LLM 成本；所有者对滥用无感知。
- **方案**：A. 创建时强制默认 7 天过期（上限 30 天）+ 记录访问数；B. 加分享维度限流；C. 加可选密码/访问次数（产品增强）。
- **👍 建议**：A 立即（纯后端，改动中等）；C 作为产品功能另行立项。

## 二、架构/数据类（P1）

### 7. L1 短期记忆纯内存（4 个无界字典，永不回收）
- **影响**：进程重启丢失全部会话上下文；多 worker 各记各的；长跑内存缓慢增长。
- **方案**：A. 进程内加 LRU/TTL 淘汰（cachetools）+ 会话删除联动清理；B. 迁 Redis（与 L2 同源）。
- **👍 建议**：A 先做（低成本止血）；B 属 P1-4 既定方向，随多 worker 一起。

### 8. `stats.records` / 流式 token 统计无界或恒 0
- **影响**：`records` 无界 append 慢速 OOM；流式/内核调用成本统计系统性偏低（招聘分析主链路基本不计费）。
- **方案**：A. records 改 deque(maxlen) + 用「单调计数器」替代切片做 per-request 差值；B. 流式 token 按输出字符估算（中文 ≈1.5 字/token）并标注 estimated。
- **👍 建议**：A + B（A 我已在评估改造量；B 改动小、收益大）。

### 9. 三套 job 缓存：无锁 + 非原子 + 无容量上限 + 缓存 key 语义缺陷
- **影响**：并发互覆盖；`analysis_cache` key 用 `jd_text[:3000]` 截断（前 3000 字相同即串档）；key 不含画像/分页；缓存无限膨胀。
- **方案**：A. 统一抽 `AtomicJsonStore`（锁 + 原子写 + LRU 淘汰），key 纳入画像版本/分页；B. 迁 SQLite/PG（中期）。
- **👍 建议**：A（我已在分批修原子写；key 语义修正 + LRU 属中等改动，列入近期）。
