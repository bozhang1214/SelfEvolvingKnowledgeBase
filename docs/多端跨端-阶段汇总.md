## 4. 本次会话查出的**真缺陷**（都已修，且大多带机械守卫）

这几项是本阶段最有价值的产出——它们都不是"看起来不对"，而是**在有证据之后才确认的问题**：

| # | 缺陷 | 后果 | 修法与守卫 |
|---|---|---|---|
| 1 | **L1 策略开发默认签名密钥两侧不一致**：服务端 `sha256("edge-policy:dev-only")`，端侧原文字面量 | 端侧拒绝**所有**服务端签发的策略 | 服务端改字面量；新增后端守卫**直接读 Android `build.gradle.kts`** 抽默认值比对 |
| 2 | **L1 策略时间单位不一致**：服务端**秒**、端侧按**毫秒**比较 | **每份策略立即"已过期"** | 统一为 epoch 毫秒；新增 `>10**12` 单位守卫 |
| 3 | **空间戳绑定方向反了**：配置空间 `…@512` ≠ 检索器实际 `…-int8@512` | 为 int8 调的阈值被拒、为 fp32 调的反而被应用 → **正是该约束要防的事** | 由构造保证同源（`config.copy(embeddingSpace = provider.space.id)`）；新增自检不变量项 `policy_space_stamp_same_source` |
| 4 | **R8 后卡在 `rag_provider`**：ONNX Runtime 的 JNI/反射类被剥 | 体积 −52% 但**跑不起来** | 加 `-keep class ai.onnxruntime.**`；**修复效果待重验** |
| 5 | **MindSpore Lite 0 CPU 挂起**根因 = 图内动态掩码展开链 | 鸿蒙模型链一直"跑不起来" | 删链 + 掩码改由宿主喂入 → **三项全通**（65.838 ms）；路线① 可行、**不必退路线③** |
| 6 | Android 空状态 `fillMaxSize()` 把输入栏挤出屏幕 | 真机上**整屏只有空状态、无法输入** | 改 `weight(1f)`（只有装到真机才看得见） |
| 7 | 点「新对话」后重启**跳回旧对话** | 与用户操作相反 | 新增"当前会话指针" |

另有多处**记录更正**（过时结论会持续误导后来人，故逐条订正）：
"benchmark 卡死 600s" 实为**两个产物两种失败**；"固定 shape 转换阶段就失败"**早已成功**；
"未做 Compose UI"已不成立；`convert` 硬编码转动态 ONNX → **脚本复现不出自己的关键产物**（已修 `convert-static`）。

## 6. 口径与纪律（避免误读）

- **"build+link 通过"≠"能装能起"**：鸿蒙侧多处结论只到前者，文档中均显式标注。
- **性能数字要带环境**：`65.838 ms` 是 **Linux-aarch64 CPU** 上的 benchmark，**不是鸿蒙设备数**。
- **等价性判据**：策略与模型变换的等价性一律要求**逐位相同**；出现 `1e-6` 量级差异时必须先分清
  是"语义差异"还是"运行时融合/调度噪声"（本次实测：关闭 ORT 优化后逐位相同，差异确属融合噪声）。
- **不认识的原因码原样透出**：`explainReason` 绝不返回"未知原因"——那会让新码静默消失
  （此原则当场就查出过一个未收录的 `edge_unavailable`）。
- **测试仪器本身也要被验证**：本轮为配色纪律、shell 变量、跨端密钥、单位、空间戳等同源问题
  各加了机械守卫，并**验证守卫真的会红**（不能失败的检查等于不存在）。
