# 16 · 端云协同协议（端侧宿主 ↔ SEKB）

> 面向：写端侧宿主（Android / iOS / 鸿蒙 / macOS / 车机）的人、以及排"这次为什么走了云端"的人。
> **参考实现**：`apps/android/`（Kotlin + Compose，含 96 条单测与可脚本化的端侧自检）；
> 其他端的目录与开工须知见 `apps/README.md`。
> 设计动机见 [RFC-端云协同与端侧Agent](../RFC-端云协同与端侧Agent.md)；本文只写**已实现**的接口契约。
> **纪律**：本文每个字段都能在代码里指到出处（见文末 §9）；改代码不改本文 = 协议漂移。

---

## 1. 一句话

端侧宿主只做四件事：**换设备凭证** → **聊天（SSE）** → **上报路由事件** → **查自己的执行位置**。
云端负责"端侧答不了的部分"，并把**本次执行位置**如实回给客户端——用户有权知道自己的数据出没出端。

---

## 2. 设备身份（RFC §8 的 S1）

### 2.1 换证：`POST /api/v1/device/enroll`

用**用户 token**（`POST /api/v1/auth/login` 拿到的）换取**设备 token**。设备首次接入时调一次，
把 `device_token` 存进系统密钥库（Android 参考实现用 **Keystore AES-GCM**，
见 `apps/android/.../device/DeviceCredentialStore.kt`）。

```http
POST /api/v1/device/enroll
Authorization: Bearer <用户 token>
Content-Type: application/json

{"name": "我的 Pixel", "platform": "android", "app_version": "0.1.0",
 "embedding_space": "BAAI/bge-small-zh-v1.5@512"}
```

```json
{"device_id": "9f3c1a2b7d4e5f60", "device_token": "eyJ...", "token_type": "Bearer",
 "expires_in_hours": 720, "scope": "edge"}
```

| 字段 | 说明 |
|---|---|
| `device_id` | 服务端生成（16 位 hex）。**端侧必须持久化**，吊销与统计都按它分片 |
| `device_token` | **只在本次响应里出现一次**，服务端只存 jti。丢了就重新 enroll |
| `expires_in_hours` | 默认 720（30 天）；到期前用 refresh 轮换，不要等过期 |
| `scope` | 固定 `edge`：可聊天、可上报、可同步会话；**不能**读写知识库 |

### 2.2 轮换：`POST /api/v1/device/refresh`

设备 token 调，返回新 token，**旧 token 立刻失效**（不是"到期才失效"）。
端侧应在启动时检查剩余有效期，少于 1/3 就轮换。

### 2.3 心跳：`POST /api/v1/device/heartbeat`

```json
{"app_version": "0.1.0", "embedding_space": "BAAI/bge-small-zh-v1.5@512"}
```

更新服务端的 `last_seen_at` 与版本戳。**只接受设备 token**（用户 token 会 403——
否则 `last_seen` 与版本戳可以被伪造成任意值）。

### 2.4 查询与吊销（网页端/用户操作）

| 端点 | 凭证 | 作用 |
|---|---|---|
| `GET /api/v1/device/list` | 用户/设备 token | 列出本用户设备；`current_device_id` 标识"我是哪台" |
| `DELETE /api/v1/device/{device_id}` | **仅用户 token** | 吊销（手机丢了唯一的止损手段） |

⚠️ **设备不能吊销自己**（403）：被攻破的设备不能"自杀灭迹"。
吊销他人的 `device_id` 返回 404（不区分"不存在"与"不是你的"，避免探测）。

### 2.5 权限边界（写死在代码里，不要指望客户端自律）

| 能力 | 用户 token | 设备 token |
|---|---|---|
| 聊天（含 SSE 流式） | ✅ | ✅ |
| 会话读写/同步 | ✅ | ✅ |
| 路由事件上报 | ✅ | ✅ |
| 知识库读写（`/api/v1/knowledge`、`/api/v1/upload`） | ✅ | ❌ 403 |
| 创建/撤销公开分享（`/api/v1/share`） | ✅ | ❌ 403 |
| 吊销设备 | ✅ | ❌ 403 |

理由：设备凭证长效（30 天）且存在客户端本地；一旦泄漏，它能做的应当尽可能少。
设备的"读知识"路径是聊天里的 RAG，不经过知识库路由。

## 3. 聊天（含执行位置）

### 3.1 非流式：`POST /api/v1/chat/`

```json
{"message": "端侧推理为什么省电？", "conversation_id": null}
```

响应在原有字段之外多了 **`execution`**（RFC §8 的 S3）：

```json
{"conversation_id": "c-1", "message": "...", "intent": "chitchat",
 "intent_confidence": 0.9, "metrics": {...}, "trace_id": "...", "degraded": false,
 "execution": {
   "primary_plane": "edge", "primary_role": "executor", "model": "qwen3.5-4b",
   "reason": "edge_preferred", "tier": "default",
   "escalated": 0, "by_plane": {"edge": 2, "cloud": 1},
   "edge_decided": 2, "edge_completed": 2, "latency_ms": 412.5,
   "versions": {"edge_model": "qwen3.5-4b", "cloud_model": "deepseek-flash",
                "tier": "default", "embedding_space": "BAAI/bge-small-zh-v1.5@512",
                "tool_schema": "unknown"},
   "roles": [{"role": "executor", "plane": "edge", "model": "qwen3.5-4b",
              "reason": "edge_preferred", "escalated": false, "signals": [],
              "latency_ms": 412.5}]}}
```

| 字段 | 端侧该怎么用 |
|---|---|
| `primary_plane` | **必须显示**给用户（"本机完成" / "已上云"）——这是"可证明的隐私"的可见面 |
| `by_plane` / `escalated` | 调试面板：一次问答里各平面参与了多少角色 |
| `reason` | 出问题时告诉用户原因，如 `output_over_edge_budget(600>300)` |
| `versions` | 与本地版本戳比对，不一致就**重算**而不是复用缓存（RFC §4.5-F） |

### 3.2 流式：`POST /api/v1/chat/stream`（SSE）

`Content-Type: text/event-stream`，每行 `data: {json}\n\n`：

| `type` | 载荷 | 端侧行为 |
|---|---|---|
| `thinking` | `{"content": "正在检索…"}` | 显示进度（来自图节点名，不是模型思考） |
| `token` | `{"content": "端"}` | **追加**到当前气泡 |
| `done` | `{"meta": {...}}` | 收尾；`meta.execution` 就是 §3.1 的 `execution` |
| `error` | `{"detail": "..."}` | 展示错误；`detail` 已面向用户 |

同一会话并发流式请求会被拒（`error` 事件提示"正在回复中"）——**端侧要自己排队**。

## 4. 路由事件上报（RFC §8 的 S2）

端侧每次**自己**完成或升级一次推理，都上报一条：

```http
POST /api/v1/edge/route-events
Authorization: Bearer <设备 token>

{"event_id": "dev9f3c-1726xxx-0001", "role": "chat", "plane": "edge",
 "reason": "edge_preferred", "model": "qwen3.5-4b", "tier": "default",
 "input_tokens": 812, "output_tokens": 96, "latency_ms": 1240.0,
 "escalated": false, "signals": [], "versions": {"app": "0.1.0"}}
```

* `event_id` 是**幂等键**：断网重传不会造成重复统计（服务端返回 `duplicated: true`）。
* `plane` 只能是 `edge` / `cloud`，否则 422。
* 服务端会打上 `source: "device"`，与它自己产生的事件区分开。

**为什么必须上报**：`edge_completion_rate`（端侧完成率）与 `escalation_rate`（升级率）
是端云协同**唯一的两个北极星指标**，而端侧自己处理的那部分不经过服务端——不上报，
这两个数字就永远只是"服务端看到的那一半"。

| 端点 | 作用 |
|---|---|
| `GET /api/v1/edge/routes/stats` | 两个北极星指标 + `by_plane` / `by_reason` 分布 |
| `GET /api/v1/edge/routes?limit=50` | 最近事件（倒序），回答"这次为什么走端/走云" |

## 6. 升级信号（客户端侧同样适用）

服务端判定升级用这 6 类（`plane_router.evaluate`）；端侧宿主自建推理时应**复用同一套语义**，
否则两边的"升级率"不可比：

| 信号 | 判据 | 客户端可做的动作 |
|---|---|---|
| `json_invalid` | 要求 JSON 但解析失败 | 重试一次 → 仍失败则升级 |
| `empty` | 输出为空 | 升级 |
| `degenerate` | 循环重复/单字符刷屏（≥40 字符起判） | 升级 |
| `timeout` | 首字超阈值（默认 800ms） | 升级 |
| `low_confidence` | 出现"我不确定/无法回答"等标记 | 升级 |
| `tool_hallucination` | 引用了未注册的工具名 | 升级并纠正提示词 |
| `context_overflow` | 输入超端侧预算（默认 2048 token） | **事前**就不走端侧 |

**流式的前缀守卫**：端侧若要在流式里升级，必须"先攒一小段再放行"
（SEKB 默认 `stream_guard_chars=60`）——已经吐给用户的字符收不回，改道只能发生在用户看到之前。
前缀判定**不含 `json_invalid`**：半截 JSON 必然不合法。

## 7. 版本戳（跨端交换必须带）

| 戳 | 取值来源 | 不一致时的后果 |
|---|---|---|
| `edge_model` | 端侧档位模型名 | 端↔云结果不可比 |
| `cloud_model` | 服务端主模型名 | 同上 |
| `tier` | `short` / `default` / `quality` | 预算算错，判去错误的平面 |
| `embedding_space` | 如 `BAAI/bge-small-zh-v1.5@512` | **向量不可比**，RAG 结果错乱（最危险的一个） |
| `tool_schema` | 工具集标识 | 工具调用参数错位 |

**规则：戳不一致 → 重算，不要复用缓存**。

---

## 8. 错误码速查

| 码 | 端侧该做什么 |
|---|---|
| 401 | 用户 token 过期 → 重新登录；设备 token 失效（被吊销/已轮换）→ 走 enroll |
| 403 | 用了设备 token 调了资产类接口 → 改成让用户在网页端操作 |
| 404 | 吊销设备时"设备不存在"（也可能是不属于你） |
| 422 | 上报字段非法（如 `plane` 不是 edge/cloud） |
| 429 | 设备数超上限（默认 20 台/用户）→ 先吊销不用的 |
| 503 | 设备凭证校验暂不可用（服务端存储异常）→ 退避重试 |
