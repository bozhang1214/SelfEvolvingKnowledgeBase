# 多端跨端 · 鸿蒙端方案（M6 收口 → M7 落地，对标 Android「功能完整可用」）

> **口径**（owner 2026-10-25 指示）：鸿蒙端的验收标准**与 Android 端侧 App 同级**——**功能完整可用**；
> **当前没有真机，全部在鸿蒙模拟器上验收**。
>
> **依据**：[`RFC-多端跨端方案.md`](RFC-多端跨端方案.md)（v1.1.0，owner 已确认；§2.3 是四端对等的验收清单 F1–F10）
> + [`多端跨端-KMP方案.md`](多端跨端-KMP方案.md) + [`apps/README.md`](../apps/README.md)（四端状态表）

## 0. 结论先行

| # | 结论 |
|---|---|
| 1 | **端侧推理最小闭环已打通**：模拟器上 HAP 装起、NAPI↔KMP 通（`ping=42`）、MindSpore Lite 出向量（`elemNum=262144 firstFloat=173347`，设备持久化 hilog 为证） |
| 2 | **应用层几乎为零**：F1–F8 八项功能级验收，Android 8/8 落地，**鸿蒙 0 项完整落地**（F8 只有一个原因码文案）。缺网络/权限/存储/凭证/检索/导航/测试/契约 |
| 3 | **RFC 里"M7 的唯一阻塞（真机+签名）"已不存在**：① 未签名 HAP 在模拟器**能装**（实测）；② `hapshell/build-profile.json5` **已含签名材料**且 `~/.ohos/config/` 下 `.cer/.csr/.p12/.p7b` 都在（10-08 16:17）；③ owner 已把验收环境改为模拟器/Preview |
| 4 | **最优路径不是重写，而是把 Android 已经验证过的三件东西搬过来**：共享层（KMP 37 文件/4,394 行）、契约夹具（37 case）、验收套路（自检 PASS/FAIL/SKIP + 同一张检索表）。ArkUI 侧已有 `EdgeAgent` 边界契约与 `Chat.ets` 骨架，**接线只需替换 `currentAgent()` 一行** |
| 5 | **工作量**：M6 收口 **1–2 天**；M7 主体沿用 RFC 的 **12–16 天**，本方案拆成 H0–H8，每阶段都有可证伪验收 |

| 6 | **先例边界（估算前必读）**：iOS 严格说只完成到"**四个端口 + 自检页**"——**没有**聊天/文档/设置 UI，F2/F3/F4/F6 的端侧 UI 路径未做（源码 `apps/ios/App/` 仅 1,171 行，UI 只有自检页）。而 owner 对鸿蒙的口径是**功能完整可用（含 UI）**，所以**不能拿 iOS 的 ≈2 天当鸿蒙的工期**；UI 规模应参照 Android（`apps/android/app/src/main` 25 文件 / 4,785 行，其中 `ui/` 占大头）。本方案的 H8 因此是"完整 UI"而不是"自检页 + 四端口" |

**一句话**：鸿蒙现在等于"有发动机、没有车"。方案的核心是把**共享层编到 ohos**（一次性投入，四端共用），再把**五个端口**在鸿蒙上各落一个实现，最后把 UI 接上——每一步都用**同一套 Android 已经在跑的自检/契约/评测**来判定，而不是新造标准。

### 1.3 结构性缺口（按阻塞强度排序）

1. **共享层完全没接**：`knspike/settings.gradle.kts` 只 `include(":knspike")`；`apps/shared` 只有 android/ios/macos 目标，**无 `ohosMain`** → 缺 `Clock`/`Hmac`/`Digests` 的 `actual`。
2. **真实嵌入实现零引用**：`kotlin-pending/MindSporeBgeEmbedding.kt` 不在任何 sourceSet，全仓唯一引用是防 double free 的守卫 grep。
3. **`vocab.txt` 没进包**（HAP 内 18 个文件里没有它）→ "文本→token"在端上没有输入源。
4. **Chat 页不可达**：`main_pages.json` 注册了 `pages/Chat`，但 `EntryAbility` 只 `loadContent('pages/Index')`，全工程无 `router`/`Navigation`。
5. **无权限、无存储、无网络**：无 `requestPermissions`、无 `@kit.ArkData`（relationalStore/HUKS）、无 `@kit.NetworkKit`。
6. **无流式、无路由、无工具闸门**（共享逻辑零调用点）。
7. **无测试与契约接入**：`find apps/harmony/spike -type d -name '*[Tt]est*'` 为空；`knspike` 无 test 依赖。
8. **包体与 ABI**：HAP 100 MB（模型 94.8 MB），且**同时打 arm64-v8a + x86_64**；而模拟器实例是 **arm**（见下）→ 一半 native 体积白费；release/混淆未做。
9. **待接实现的口径已过期**：`kotlin-pending` 那份用的是旧输入集（`input_ids`/`attention_mask`/`token_type_ids`），而当前可运行模型吃 **`sekb_additive_mask_zero`（float32）** → 接线时必须重写这一段。

## 2. 目标架构（与 Android 同构）

```
apps/
├── shared/            ★ KMP：core(纯逻辑) + ports(端口) + androidMain/ohosMain/appleMain(actual)
├── contract/          ★ 语言无关契约夹具（37 case，鸿蒙要加 runner）
└── harmony/
    ├── spike/knspike/        KMP 产物 libkn.so（编进 :shared + MindSpore 端口）
    └── spike/hapshell/       DevEco 工程：entry(ArkUI) + cpp(NAPI) + rawfile(.ms/vocab)
```

| 层 | Android（参照） | 鸿蒙（目标） |
|---|---|---|
| UI | Jetpack Compose（4 页：Chat/History/Documents/Settings） | **ArkUI 原生**，同 4 页 + 导航（`Chat.ets` 已有骨架） |
| 逻辑 | `apps/shared`（唯一实现） | **同一份** `apps/shared`（经 OHOS Kotlin fork 编到 `ohosArm64`） |
| 传输 | OkHttp → `HttpTransport` | `@ohos.net.http`/`rcp` 实现 `HttpTransport`（或 libcurl，见 §4 S1） |
| 嵌入 | ONNX Runtime Android（`OnnxBgeEmbedding`） | **系统 MindSpore Lite**（`MindSporeBgeEmbedding`，口径需按 additive-mask 重写） |
| 向量库 | SQLite（`SqliteVectorStore`） | `relationalStore`（`VectorStore` + `DocumentRegistry`） |
| 凭证 | Keystore | **HUKS**（`CredentialStore`） |
| PDF | PDFBox | OHOS PDF 能力或 C 库（`PdfExtractor` 同四类结果） |
| 端侧 LLM | 宿主 Ollama（`adb reverse`） | **先宿主/云端**（符合 RFC D4）；宿主直通用 `hdc rport` |
| 自检 | `SelfTest.kt`（38 项，输出 `SEKB_SELFTEST` PASS/FAIL/SKIP） | 同格式自检（输出 `SEKB_HARMONY_SELFTEST`），项名尽量与 Android 同名以便对比 |

**一条硬边界（RFC M3 不变量）**：端侧向量必须与云端**同空间戳**（fp32 `BAAI/bge-small-zh-v1.5@512`）；int8 是另一个戳，换模型必须原地重算索引。

**代码里实际存在的端口（6 个，鸿蒙各落一个实现）**：

| 端口 | 定义位置 | 鸿蒙实现手段 |
|---|---|---|
| `HttpTransport`（`postJson`/`get`/`postJsonStream(onLine)`） | `apps/shared/.../net/HttpTransport.kt` | libcurl（S1 已定，见 C2）或 `@ohos.net.http` |
| `EmbeddingProvider`（`space`/`isOnDevice`/`embed`） | `.../embed/EmbeddingProvider.kt` | **系统 MindSpore Lite**（推理已跑通，口径需重写） |
| `VectorStore`（`upsert`/`deleteBySource`/`search`/`all`…） | `.../rag/VectorStore.kt` | `relationalStore` |
| `DocumentRegistry`（`upsert`/`list`/`get`/`delete`） | `.../rag/DocumentRegistry.kt` | `relationalStore` |
| `CredentialStore`（`load`/`save`/`clear`） | `.../device/CredentialStore.kt` | **HUKS** |
| `PolicyStore`（`loadActive`/`loadPrevious`/`save`/`rollback`） | `.../policy/PolicyStore.kt` | `preferences` + 文件双槽（L1 可后置） |

> ⚠️ `docs/多端跨端-KMP方案.md` §3.2 里规划的 `FileSourcePort`/`TextExtractPort`/`DeviceToolPort`/`PlatformEnv`/`EdgeConfig` **在代码里并不存在**——文件读取、PDF 抽取、设备工具目前由**各端自己实现**（Android：`ui/PdfExtractor.kt`/`ui/DocumentImporter.kt`/`tools/AndroidDeviceTools.kt`）。鸿蒙照此办理，不要去找这些接口。
> 平台 `actual` 目前只有 4 个文件（`androidMain`/`appleMain` 各 `Clock`/`Hmac`），鸿蒙要补 `ohosMain` 的 `Clock`/`Hmac`（`Digests` 也在 `core/`）。

## 3. 分阶段实施（H0–H8，每阶段都有可证伪验收）

> 每阶段结束都要**在模拟器上**留下可复现命令 + 原始输出；未验的必须单列（照 Android `VERIFICATION.md` 的纪律）。

| 阶段 | 内容 | 验收（可证伪） | 预估 |
|---|---|---|---|
| **H0** 流水线与基线 | 新增 `scripts/harmony.sh`（对标 `android.sh`/`ios_app.sh`）：`build \| install \| start \| selftest \| log \| crash`，封装 `hdc` 路径、`DEVECO_HOME`、`HVIGOR_USER_HOME`、`HOME` 沙箱三坑；修正 §1.4 的三处过时文档 | `bash scripts/harmony.sh selftest` 一条命令完成"构建→装→起→抓 hilog→抓 cppcrash"，输出与手工一致 | 0.5–1 天 |
| **H1** 共享层编到 ohos | `apps/shared` 加 `ohosArm64`（+可选 `ohosX64`）目标与 `ohosMain`（`Clock`/`Hmac`/`Digests` actual）；`knspike` 依赖 `:shared`；**interop smoke**（对标 iOS `ios.sh smoke 5/5`：HMAC/SHA256 公知向量、canonical JSON 与 Python 一致、`ToolCallJson` 导出可用、`Fmt` 与 Android 逐字符一致） | smoke 全绿；`libkn.so` 符号表里出现 `com.sekb.shared.*` 的导出 | 1–2 天 |

| **H6** 端侧嵌入验收（关键） | 嵌入与 Android **同空间**（fp32）；sanity 余弦（Android 0.244）、L2 范数 1.0000、确定性；`rag_retrieve` 首条分（Android/iOS 0.630）；**检索评测同表** | 阈值 0.20–0.60 的 `Hit@1/Hit@3/MRR/误召回` 与 Android **逐项相同**（0.40 → 26/30、30/30、0.928、0/3）；顺手定位 §1.4 的 dtype 不一致 | 2–3 天 |
| **H7** 路由 / 守卫 / 闸门 / 隐私 | 复用共享层：`PlaneRouter`（6 类信号 + R10 本机判据）、`StreamGuard`（零外泄）、`ToolRegistry` 三闸门 + `KbSearchTool`；`ChatOrchestrator` 端侧优先与改道 | 自检 `router_decision`/`privacy_device_only_local_gate`/`permission_gate`/`audit_stats`（越权拦截率）；契约夹具 signals/privacy 全绿 | 1.5–2 天 |
| **H8** UI 完整化 + 自检 + 打包 | ArkUI 四页 + 导航（让 `pages/Chat` 可达）+ **流式逐字**；接 `EdgeAgent`（`currentAgent()` 换成 NAPI 实现，UI 一行不改）；自检输出 PASS/FAIL/SKIP 表；release 构建 + **ABI 只留 arm64** + 包体目标 | F1–F10 **逐条**过；自检 FAIL=0 且项名可与 Android 对照；release HAP 体积记录（目标：模型外增量 ≤ Android 的 5 MB 量级） | 3–4 天 |
| **H9**（并行/后续） | 真机性能（等硬件，RFC §7 已单列）；本地 LLM（llama.cpp） | 不阻塞本期"功能可用" | — |

**关键路径**：H1 → H5 → H6 是唯一的长杆（共享层 + 嵌入口径 + 同表）；H3/H4/H7 都是"照 Android 同构实现"，风险低。
