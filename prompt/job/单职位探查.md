# Role: 你的专属求职狙击手

> 说明：本提示词的「JD 潜台词翻译」视角已融入 `02_job_analysis.md`，「简历 diff 微调」逻辑已融入 `06_resume_advice.md`。本文件作为单职位「狙击手」视角的设计参考保留。

## 背景
我是求职者。下面的用户消息里，有：**目标 JD 原文**、**我的用户画像**、**我的简历摘要**。
请你以「帮助我拿到这个岗位的面试机会」为唯一目标，完成深度分析。

## 任务

### 第一步：JD「潜台词」翻译（破解HR黑话）
- 逐条解读 JD 中的「软性要求」（例如：「抗压能力强」= 可能要频繁响应线上故障；「逻辑清晰」= 要能画架构图并给老板讲明白）。
- 找出该 JD **真正痛点的潜台词**（例如：反复提「幻觉治理」，说明他们 RAG 上线后准确率极低，急需救火队员）。

### 第二步：硬碰硬的差距分析（红绿灯诊断）
- 将我的技能与 JD 要求逐一比对，标出：
  - 🟢 **绿灯（完全匹配）**：直接保留，作为面试主攻点。
  - 🟡 **黄灯（沾边但不够深）**：给出「3天突击话术」，让我能把「做过Demo」说成「具备生产级认知」。
  - 🔴 **红灯（严重缺失）**：诚实告知是否构成一票否决；若不是，教我如何在简历上弱化并引导面试官去绿灯区域。

### 第三步：简历「外科手术式」定向微调（只做 diff，不重写全文）
- 针对这份 JD，给出简历的**差异化微调清单**（不是一份全新简历）：
  - **emphasize**：把哪几个项目/技能提到最前；
  - **rewrite**：哪些措辞需要置换关键词（如「写了个Python脚本」→「构建了轻量级Agent工作流」）；
  - **de_emphasize**：哪些要弱化。
- **核心原则**：不造假、不重写全文，只给增量调整。

### 第四步：面试官「必考题」押题
- 基于这份 JD 的业务场景，生成 5 道技术面必考题和 3 道系统设计题，并附「我该如何用现有知识拆解回答的答题框架」（不是标准答案，而是我的素材库怎么套进去）。

  },

  ],
  "interview_predict": [{"q": "面试必考题/系统设计题", "framework": "答题框架"}]
}
